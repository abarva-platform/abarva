CLOUD MIGRATION BENCHMARKS AND AI ENABLEMENT PATTERNS
Source: Gartner Cloud Migration Study 2025, AWS Migration Intelligence, AbarVa Assessment Data
Updated: 2025.Q1

OVERVIEW

Cloud migration is a prerequisite for enterprise AI at scale, not an optional infrastructure investment. All major AI frameworks — PyTorch, TensorFlow, Hugging Face, and the leading managed AI services (Azure OpenAI, AWS Bedrock, Google Vertex AI) — require cloud compute for training at scale. On-premise AI is possible for inference on existing models, but it cannot support the elastic GPU compute, large-scale training, and real-time data pipelines that differentiate leading AI programmes.

AbarVa's engagement data shows that the most common cloud migration failure is not technical — it is strategic. Organisations that migrate infrastructure without defining AI use cases first spend 38-47% more than planned and achieve only a fraction of the AI enablement benefit. The correct frame: cloud migration is an AI enablement investment. The business case is AI capability unlocked, not infrastructure modernised.

Key headline findings:
  Enterprise workloads in cloud (2025): 48%; projected 2028: 64%
  Lift-and-shift performance improvement: +8% (limited benefit)
  Re-architect performance improvement: +68% (transformational benefit)
  Cloud migration ROI at 5 years: 3.4x (re-architect), 1.8x (lift-and-shift)
  Average cloud overspend in year 1: 38-44% above optimal — FinOps essential
  Annual cloud cost savings opportunity with FinOps: $12-48M (large enterprise)


CLOUD MIGRATION MARKET OVERVIEW

Enterprise workload distribution (2025):
  In public cloud: 48%
  Remaining on-premise: 52%
  Of remaining on-premise: 82% are suitable for cloud migration
  Unsuitable for cloud: 18% (latency-sensitive trading, regulated PHI at certain clients, classified workloads)

Migration pace at current investment:
  Estimated time to migrate all suitable on-premise workloads: 5-8 years
  Acceleration required for AI competitiveness: 3-5 year timeline (aggressive but achievable)
  Key barrier: lack of cloud talent, not technology — 68% of migration delays are human-capital related

Cloud provider market share (enterprise, 2025):
  AWS: 32%
  Microsoft Azure: 28%
  Google Cloud: 13%
  Multi-cloud: 27% (growing — organisations using 2+ cloud providers for different workloads)


MIGRATION APPROACH BENCHMARKS

APPROACH 1: LIFT-AND-SHIFT (REHOST)
Description: Move application to cloud with no architecture changes (equivalent of moving a VM image)
Prevalence: 44% of first-wave migrations — the default starting point
Timeline: 4-12 weeks per application (fast)
Performance improvement post-migration: +8% (latency improvement from modern hardware, but no architectural benefit)
Cost reduction post-migration: +2% (marginal — on-demand cloud pricing without optimisation is expensive)
Cost per server: $8,400-24,000
AI enablement: minimal — data is in cloud storage but applications have not changed; AI pipelines require additional work
Best use: legacy applications that must be cloud-hosted but are not prioritised for transformation; buy time for longer re-architect

APPROACH 2: RE-PLATFORM
Description: OS or database upgrade, moving to cloud-native equivalent (e.g., SQL Server on VMs → Azure SQL Managed Instance)
Prevalence: 34% of migrations
Timeline: 2-6 months per application
Performance improvement: +34% (significant — cloud-native database engines deliver materially better performance)
Cost reduction: +18% (cloud-native auto-scaling eliminates over-provisioning)
Cost per application: $280,000-620,000
AI enablement: moderate — cloud-native data stores are connectable to AI pipelines; some transformation required
Best use: data-producing applications (transactional databases, ERP, CRM) where data needs to feed AI

APPROACH 3: RE-ARCHITECT (CLOUD-NATIVE)
Description: Redesign application using cloud-native patterns (microservices, serverless, managed services, API-first)
Prevalence: 20% of migrations — minority but growing as organisations see the performance gap
Timeline: 6-18 months per application (significant investment)
Performance improvement: +68% (transformational)
Cost reduction: +34% (auto-scaling, managed services, no over-provisioning)
Cost per application: $480,000-1.2M
AI enablement: maximum — cloud-native applications are built to integrate with AI services; real-time data available
Best use: customer-facing applications, data-generating applications, applications central to AI use cases
Cloud migration ROI at 5 years: 3.4x (re-architect) vs. 1.8x (lift-and-shift)

MIGRATION APPROACH SELECTION CRITERIA:
  Application generates data critical to AI use cases: prioritise re-architect
  Application is legacy, low business value, needs to move for compliance: lift-and-shift is acceptable
  Application is a database or data store: re-platform minimum; re-architect preferred
  Application will be sunset within 3 years: lift-and-shift only (no point in re-architecting)


MIGRATION COST BENCHMARKS

Per-application migration costs (varies by approach and complexity):
  Simple app, lift-and-shift: $8,400-24,000 per server
  Medium complexity, re-platform: $280,000-620,000 per application
  High complexity, re-architect: $480,000-1.2M per application
  ERP migration (SAP S/4HANA): $4.8-18M total project (most complex category)
  Epic EHR cloud migration: $2.4-8.4M total project (healthcare specific)

Total enterprise migration cost benchmarks:
  Mid-market organisation ($1-5B revenue, 200-500 applications): $40-180M over 4-5 years
  Large enterprise ($5-15B revenue, 500-1,500 applications): $180-620M over 5-7 years
  Fortune 500 (1,500-5,000 applications): $620M-2.4B over 6-10 years

Common cost underestimation factors:
  Data migration cost: typically underestimated by 40-60%
  Testing requirement: business-critical systems need 6-9 months of testing — often not budgeted
  Change management: workforce adaptation to cloud-native tools — often zero-budgeted
  Legacy integration: on-premise systems don't cleanly disconnect — integration work underestimated by 28%
  AbarVa finding: 74% of cloud migration projects exceed initial budget by > 20%


AI WORKLOAD CLOUD REQUIREMENTS

TRAINING:
  GPU/TPU requirement: training large ML models requires 8-512 GPUs; only cloud provides elastic GPU compute
  Cloud GPU instances: AWS p3/p4 (NVIDIA V100/A100), Azure NC/ND, GCP A3 (H100)
  Training cost at scale: $2,400-14,000 per training run (GPT-scale training: $2-8M)
  On-premise alternative: feasible for small models; not feasible for LLM or large computer vision models
  Key finding: organisations cannot compete in AI capability without cloud GPU access

INFERENCE (PREDICTION SERVING):
  On-premise viable: small-scale inference (100-1,000 requests/second) can run on-premise on CPU/GPU servers
  Cloud preferred: elastic scaling, managed endpoints, automatic load balancing
  Key cloud services: AWS SageMaker Endpoints, Azure ML Online Endpoints, Vertex AI Prediction
  Cost at scale: inference is typically 10x the compute cost of training (run continuously vs. train once)

DATA PIPELINES FOR AI:
  Object storage requirement: S3 (AWS), ADLS Gen2 (Azure), GCS (Google) — all AI frameworks assume object storage
  Streaming pipeline: Kinesis (AWS), Event Hubs (Azure), Pub/Sub (GCP) — required for real-time AI
  Transformation: cloud-native Spark (Databricks, EMR, Dataproc) far cheaper than on-premise Hadoop clusters
  AbarVa finding: organisations with on-premise-only data pipelines add 6-12 months to AI deployment timeline

MANAGED AI SERVICES:
  Azure OpenAI: enterprise GPT-4/GPT-4o with data residency and security controls
  AWS Bedrock: multi-model (Anthropic Claude, Amazon Titan, Meta Llama) with enterprise security
  Google Vertex AI: Gemini + custom model training + feature store + MLOps
  Cost advantage vs. self-hosted: managed services 40-60% cheaper per inference than self-hosted LLM at scale
  AbarVa recommendation: use managed AI services for GenAI; self-hosted for proprietary/fine-tuned models only


CLOUD PLATFORM SELECTION CRITERIA FOR AI

MICROSOFT AZURE:
  Best for: Microsoft-integrated organisations (Office 365, Teams, Power Platform ecosystem)
  AI advantage: Azure OpenAI Service (enterprise-grade GPT-4, exclusive models), Copilot integration
  Healthcare: Epic on Azure is the most common Epic cloud architecture; Azure best for Epic AI integration
  FS advantage: strong compliance certifications; partnership with major FS regulators
  Data platform: Azure Synapse + Azure ML (solid; not as Python-native as Databricks-first approach)
  Cost: premium pricing relative to GCP; similar to AWS for most workloads
  AbarVa recommendation for Azure: organisations already in Microsoft ecosystem, healthcare, regulated FS

AMAZON WEB SERVICES (AWS):
  Best for: organisations with Python-native ML teams; startup-influenced technical culture
  AI advantage: AWS SageMaker (most mature MLOps platform), Bedrock (broadest model selection), Trainium chips for cost-efficient training
  Data platform: Redshift (analytics), EMR (Spark), Glue (ETL) — mature but fragmented; Databricks recommended as unifier
  Retail advantage: strong AWS retail vertical (Forecast, Personalize); many retailers on AWS ecosystem
  Cost: competitive base pricing; complex billing requires FinOps from day one
  AbarVa recommendation for AWS: Python-forward ML teams, retail, high-volume inference at cost efficiency

GOOGLE CLOUD PLATFORM (GCP):
  Best for: analytics-heavy organisations; organisations with cutting-edge ML innovation ambitions
  AI advantage: BigQuery ML (SQL-based ML, fastest path to first model for analysts), Vertex AI (strong MLOps), Gemini models
  Data advantage: BigQuery is the best-in-class analytical data warehouse for pure analytics workloads; 6-14x faster than alternatives for complex analytical queries
  Cost: most competitive pricing on analytics (BigQuery on-demand pricing); less competitive for general compute
  ML innovation: GCP has deepest native integration with Google Research advances (TPUs, JAX, AlphaFold)
  AbarVa recommendation for GCP: analytics-heavy workloads, organisations requiring cutting-edge ML capability, when BigQuery would be primary data platform

MULTI-CLOUD STRATEGY:
  When appropriate: specific capabilities require different providers (e.g., Azure for Microsoft integration + GCP for BigQuery analytics)
  Cost of multi-cloud: 12-18% premium over single-cloud due to data egress, management complexity, and security overhead
  Governance risk: multi-cloud without unified governance creates shadow infrastructure
  AbarVa recommendation: avoid multi-cloud unless specific compelling capability justifies it; start single-cloud, add second only with specific use case


DATA MIGRATION RISK FACTORS

DATA VOLUME:
  Data volume growth rate: 23% annually (industry average) — migration takes longer than planned because data grows during migration
  Most organisations underestimate migration data volume by 30-40%
  Practical impact: migration timeline extends; interim solution (sync both source and target during migration) required for live systems

DATA QUALITY DISCOVERY:
  Data quality issues discovered during migration: 22% of records have quality issues (on average)
  Discovery timing: issues surface only when data is moved to a new system with different validation rules
  Financial impact: data quality remediation mid-migration costs 2.4x more than addressing before migration
  AbarVa recommendation: 2-3 months of data profiling before migration begins — surface issues in controlled environment

MIGRATION TESTING REQUIREMENTS:
  Business-critical systems: 6-9 months of parallel operation testing minimum
  Data integrity testing: compare source vs. target for 100% of records on critical tables (not sampling)
  Performance testing: cloud-native query performance must meet or exceed on-premise baseline
  Rollback planning: define rollback procedure before migration (not after problems arise)

DATA GOVERNANCE DURING MIGRATION:
  Ownership: data that moves to cloud must have an owner in the new environment
  Catalogue: all migrated datasets must be registered in cloud data catalogue (do not migrate uncatalogued data)
  Classification: sensitivity classification (PII, PHI, confidential) must travel with data to new environment
  Lineage: data lineage documentation must be preserved through migration — AI compliance requires it


COST OPTIMISATION POST-MIGRATION

Average cloud overspend in first year: 38-44% above optimal — this is consistently the largest year-1 cloud problem
Root cause: lift-and-shift creates cloud-equivalent of on-premise over-provisioning; right-sizing requires operational data

FinOps implementation:
  Reduces overspend to 8-14% (from 38-44%)
  FinOps tooling: AWS Cost Explorer, Azure Cost Management, CloudHealth, Apptio Cloudability
  FinOps team: minimum 2 FTE for large enterprise; 1 FTE + tooling for mid-market
  Payback: FinOps investment pays back within 3 months for any organisation spending > $2M annually on cloud

Reserved instances and savings plans:
  Cost reduction vs. on-demand: 38-52%
  Commitment: 1-year or 3-year reserved
  Best for: predictable, steady-state workloads (data warehouse, always-on inference endpoints)
  Risk: overcommitting reserved capacity that goes unused — partial waste

Spot and preemptible instances for AI training:
  Cost reduction vs. on-demand: 60-80%
  Availability: not guaranteed — instance can be terminated with 2-minute warning
  Best for: AI training jobs that can checkpoint and resume; batch data processing
  Not appropriate for: real-time inference, live data pipelines
  Annual saving for large AI training programme: $2.4-8.4M (depending on GPU usage)

Annual cloud cost savings opportunity (large enterprise):
  FinOps programme: $12-48M annually (depending on cloud spend scale)
  Right-sizing: 18-28% cost reduction
  Spot/reserved mix optimisation: 22-34% cost reduction
  Duplicate service elimination: 8-14% cost reduction
  Total achievable optimisation: 40-60% of first-year overspend recoverable within 12 months


HYBRID AND EDGE COMPUTING CONSIDERATIONS

HEALTHCARE HYBRID:
  PHI handling: 44% of healthcare organisations keep PHI on-premise for compliance confidence
  AI architecture: de-identify data on-premise → send de-identified training data to cloud → bring model back to edge for inference on live PHI
  Epic on Azure: emerging standard; Epic FHIR API → Azure Data Lake → Azure ML pipeline
  Cost of hybrid: 12-18% premium vs. pure cloud, justified by compliance risk management

FINANCIAL SERVICES HYBRID:
  Market data and trading: 38% of market data and trading systems remain on-premise for latency (sub-millisecond requirements cloud cannot guarantee)
  Fraud detection: real-time fraud requires cloud elasticity; latency requirement (< 200ms) met by cloud with edge caching
  Core banking: 72% of large banks still have mainframe core — cloud-native customer-facing layer, mainframe back-of-house
  Regulatory: data residency requirements in some jurisdictions require specific cloud region configuration

RETAIL EDGE:
  Store-level computer vision (loss prevention, customer analytics): edge deployment reduces bandwidth 84%
  Demand sensing: real-time POS data can be processed at edge; aggregated for cloud ML training
  Edge hardware: NVIDIA Jetson (edge AI), AWS Panorama (computer vision), Azure Edge Zones
  Cost of edge vs. cloud: edge reduces ongoing bandwidth cost by 60-80% for video workloads

Hybrid architecture cost premium vs. pure cloud: 12-18% — acceptable when compliance or latency requirements justify


CLOUD MIGRATION PROGRAMME MANAGEMENT

MIGRATION GOVERNANCE:
  Cloud migration programme has unique governance requirements vs. standard IT project
  Single programme director with cloud architecture authority: 2.8x faster migration vs. committee governance
  Executive sponsor: required for cross-functional decisions (network, security, data, application teams must cooperate)
  Centre of Cloud Excellence: dedicated team for cloud standards, security baseline, and cost governance; prevents fragmented migrations

MIGRATION RISK MANAGEMENT:
  Top migration risks (by frequency):
    Risk 1: Data integrity loss during migration (28% of migrations have data loss or corruption incidents)
      Mitigation: complete data reconciliation before and after; automated comparison of record counts and checksums
    Risk 2: Performance regression after migration (34% perform below pre-migration baseline initially)
      Mitigation: performance baseline documentation before migration; performance gate before cutover
    Risk 3: Security misconfiguration in cloud (44% of cloud security incidents are misconfigurations)
      Mitigation: security baseline enforcement via IaC (Terraform, ARM); automated security posture management (CSPM)
    Risk 4: Cost overrun (38-44% over budget in year 1)
      Mitigation: FinOps implementation at migration; budget alerts and cost anomaly detection from day 1
    Risk 5: Application dependency discovery (18% of applications have undocumented dependencies)
      Mitigation: dependency mapping with cloud migration assessment tools before migration begins

MIGRATION TOOLING:
  Discovery and assessment: AWS Migration Hub, Azure Migrate, Google Cloud Rapid Assessment — automated inventory of on-premise estate
  Server migration: AWS MGN (Application Migration Service), Azure Migrate Server Migration
  Database migration: AWS DMS, Azure Database Migration Service, Google Database Migration Service
  Container migration: Kubernetes migration (most organisations re-containerise during migration)
  Assessment cost: typically $120,000-480,000 for large enterprise assessment; ROI is migration risk reduction


CLOUD SECURITY FOR AI WORKLOADS

AI workloads have specific cloud security requirements beyond general cloud security:

DATA SECURITY:
  AI training data: must be classified (PII, PHI, confidential) before moving to cloud; encryption at rest (AES-256 minimum)
  Data access control: AI training data access should be role-based; data scientists should not have production-data direct access
  Data exfiltration prevention: DLP (Data Loss Prevention) policies on cloud storage prevent sensitive training data from leaving controlled environment
  Model security: trained model weights should be treated as intellectual property; access control on model registry

COMPUTE SECURITY:
  GPU instance isolation: AI training on dedicated GPU instances prevents co-tenant interference
  Network isolation: AI training VPC (Virtual Private Cloud) isolated from production systems
  Ephemeral training: training jobs use temporary compute; no persistent access to production data after job completion

INFERENCE SECURITY:
  API gateway: all AI model endpoints behind API gateway with authentication
  Input validation: model serving endpoints validate input to prevent adversarial attacks and prompt injection
  Output monitoring: model outputs monitored for unexpected patterns (data exfiltration via model inversion)

COMPLIANCE IN CLOUD:
  Healthcare HIPAA: BAA (Business Associate Agreement) required with all cloud providers for PHI workloads; AWS, Azure, and GCP all offer HIPAA-eligible services
  Financial services: SOC 2, ISO 27001 certifications required; all major cloud providers have these
  GDPR data residency: EU customer data must remain in EU cloud regions; configure accordingly
  AbarVa recommendation: cloud security architecture review in Phase 0; do not migrate before security baseline is defined


MIGRATION AND AI TIMELINE INTEGRATION

The greatest efficiency in cloud migration is achieved when migration and AI programme development are sequenced together, not sequentially.

SEQUENTIAL APPROACH (COMMON BUT SUBOPTIMAL):
  Year 1: complete cloud migration
  Year 2: begin AI programme on cloud infrastructure
  Total time to AI value: 30+ months
  Wasted window: AI programme waiting while migration completes

PARALLEL/INTEGRATED APPROACH (ABARVA RECOMMENDED):
  Phase 1 (months 1-6): migrate data sources critical to Phase 2 AI use case; AI-enabling data on cloud first
  Phase 2 (months 4-10): AI use case development on partially-migrated data; 90-day quick win on cloud
  Phase 3 (months 6-24): continue migration of remaining applications; AI portfolio expanding in parallel
  Total time to AI value: 8-10 months (vs. 30+ months sequential)
  Migration efficiency: migration business case is stronger with AI value demonstrated early

Migration prioritisation for AI value:
  Priority 1: data sources that feed Phase 2 AI use case (first to cloud)
  Priority 2: data analytics and BI platforms (enables self-service and AI training)
  Priority 3: operational applications (ERP, EHR) — migrate after AI is producing value, not before
  Priority 4: legacy applications with no AI dependency — migrate last (or lift-and-shift for speed)
