HEALTHCARE CLOUD ADOPTION AND MIGRATION BENCHMARKS
Source: IDC Healthcare Cloud Adoption Survey 2025, HIMSS Analytics CIO Survey, Gartner Cloud Strategy Report, AbarVa Technology Assessments

CLOUD ADOPTION OVERVIEW

Cloud adoption in healthcare crossed the majority threshold in 2022 and is now the dominant infrastructure model for new deployments. 94% of health systems use at least one cloud provider. The strategic questions have shifted from "should we move to cloud?" to "how fast, which workloads, which providers, and how do we govern cost and security?" AI is the primary accelerant of cloud migration — 78% of health systems cite AI deployment as the top reason for cloud expansion.

CLOUD ADOPTION RATES:
Health systems using at least one cloud provider: 94%
Primarily cloud-based (> 60% of workloads in cloud): 28%
Hybrid cloud model (40-60% cloud): 52%
Primarily on-premise (< 40% cloud): 20%

5-YEAR TREND:
2021: 18% primarily cloud-based
2022: 22%
2023: 24%
2024: 26%
2025: 28%
Projection 2028: 46% primarily cloud-based (accelerating)

CLOUD PROVIDER MARKET SHARE IN HEALTHCARE

MICROSOFT AZURE: 37% primary cloud market share
Key advantages:
- Exclusive Epic cloud partnership: all Epic cloud hosting runs on Azure (since 2023 announcement)
- Azure Health Data Services: FHIR R4 native API service; direct Epic integration; 4-hour provisioning
- Azure OpenAI Service: HIPAA BAA available; most widely adopted GenAI in healthcare; used at 24% of Azure-primary systems
- Microsoft + Nuance DAX integration: ambient documentation AI natively on Azure
- Microsoft Copilot for Healthcare: Teams + Epic integration; clinical communication AI
- HIPAA compliance tooling: pre-built compliance controls; most healthcare-familiar
- Azure Marketplace healthcare solutions: 2,400+ healthcare ISV solutions
- Fabric for Healthcare: unified analytics and AI platform replacing Azure Synapse (2025)

AWS (AMAZON WEB SERVICES): 31% primary cloud market share
Key advantages:
- AWS HealthLake: FHIR-native data lake with built-in analytics and NLP
- Amazon Comprehend Medical: clinical NLP for condition, medication, procedure extraction; deployed at 400+ health systems
- Amazon Bedrock: managed GenAI (Claude Sonnet, Llama, Titan, Mistral) with HIPAA BAA; growing from 18% (2024) adoption
- Amazon SageMaker: ML training and deployment; used at 22% of AI-active health systems
- Amazon Transcribe Medical: clinical speech recognition; 98.4% clinical terminology accuracy
- AWS Data Exchange: healthcare data marketplace (claims data, research datasets)
- Strong ML/AI tooling: preferred by data science-led organizations; faster model iteration cycles
- Cost structure: competitive for large ML training workloads

GOOGLE CLOUD: 19% primary cloud market share
Key advantages:
- BigQuery: petabyte-scale analytics; healthcare datasets at low cost; preferred for population analytics
- Google Cloud Healthcare API: FHIR R4 + HL7 v2 + DICOM native; most complete data type coverage
- Vertex AI: unified ML + GenAI; Med-PaLM 2 (specialized clinical LLM, Mayo Clinic and Cleveland Clinic pilots)
- Looker: BI natively integrated with BigQuery; strong for clinical analytics dashboards
- Google Workspace + Healthcare API: patient communication AI
- Research strength: DeepMind's AlphaFold, Med-Gemini — translates to clinical AI pipeline
- Note: Azure partnership with Epic makes Google Cloud secondary in EHR-centric organizations

MULTI-CLOUD:
Health systems using at least two cloud providers: 76%

Multi-cloud drivers: best-of-breed AI services, vendor risk management, regulatory preference (some states require US-sovereign cloud)

CLOUD MIGRATION COST BENCHMARKS

Average migration cost per application: $280,000-620,000
Legacy data warehouse migration — Teradata to cloud: $3.8-9.2M per $1B revenue
Oracle DB on-premise to AWS/Azure: $0.8-2.4M per database
On-premise server to cloud (lift-and-shift): $8,400-24,000 per server
On-premise server to cloud (cloud-native redesign): $28,000-84,000 per equivalent workload
Timeline — large IDN full infrastructure migration: 3-5 years
Lift-and-shift vs. cloud-native redesign cost ratio: 1:2.4 (native is 2.4x more expensive upfront)
Lift-and-shift vs. cloud-native 3-year performance return: native delivers 3.8x better performance and 40% lower long-term cost

MIGRATION PHASES AND COSTS (large IDN, 10 hospitals):
Phase 1 — Collaboration and productivity (email, file share): $1.4-2.8M; 6-12 months
Phase 2 — Non-clinical applications (HR, finance, supply chain): $4.2-8.4M; 12-18 months
Phase 3 — Analytics and data warehouse: $8.4-18M; 18-30 months
Phase 4 — Clinical applications (EHR-adjacent systems): $12-24M; 24-36 months
Phase 5 — Core EHR (Epic Cloud or Oracle Cloud): $18-38M; 36-48 months (if not already on vendor cloud)
Total migration investment: $44-91M for large IDN over 3-5 years

HEALTHCARE CLOUD SECURITY

HIPAA SHARED RESPONSIBILITY MODEL:
Cloud provider responsible: physical infrastructure, platform, hypervisor
Health system (customer) responsible: data, identity and access, application security, encryption keys
Common misunderstanding: 44% of health systems believe cloud provider is responsible for patient data security
Result: 28% of cloud-hosted health data is improperly secured under customer responsibility

ENCRYPTION STANDARDS:
At-rest encryption: AES-256 required for PHI; 88% of cloud-hosted PHI is encrypted
In-transit encryption: TLS 1.2+ required; 94% compliant
Key management: health system-managed encryption keys (BYOK): 38%; provider-managed: 62%
Hardware security module (HSM) for key management: 22% (most secure; required for some federal contracts)

CLOUD SECURITY VENDORS IN HEALTHCARE:
Palo Alto Networks Prisma Cloud: CSPM (Cloud Security Posture Management) for healthcare
Wiz: cloud infrastructure security; fast-growing in healthcare; identifies misconfiguration
Orca Security: agentless cloud security for healthcare workloads
CrowdStrike Falcon Cloud Security: endpoint + cloud combined
Claroty: extends to cloud-connected medical devices

GENOME FAILURE PATTERNS IN CLOUD ADOPTION

F003 — Legacy on-premise data warehouse blocking cloud AI: Teradata and old SQL Server DW cannot integrate with cloud AI services; migration required before AI programme; 38-47% cost premium for unplanned migration
F019 — Data siloed across multiple cloud regions or providers: clinical data in Azure (Epic), financial in GCP (legacy), operational on-premise; no unified AI layer possible without data mesh or integration platform
F027 — Cloud procurement fragmented (no central governance): each hospital in IDN has separate cloud accounts; no consolidated reserved instance discounts; 44% higher cloud spend than necessary
F034 — No cloud cost baseline before FinOps programme: impossible to demonstrate FinOps savings without a pre-FinOps cost baseline; common in organizations that engage FinOps consultants without establishing Day 0 metrics
F041 — Cloud-native AI requires skills not yet in health system: lift-and-shift migrations do not build the Kubernetes, MLOps, and cloud-native skills required for AI; creates talent gap even after cloud migration

CLOUD ARCHITECTURE PATTERNS FOR HEALTHCARE AI

AZURE REFERENCE ARCHITECTURE (Epic-centric organization):
Layer 1 — Ingestion: Epic HL7 v2 ADT → Azure Event Hubs (streaming); Epic Clarity SQL → Azure Data Factory (batch)
Layer 2 — Storage: Azure Data Lake Storage Gen2 (ADLS2); Delta Lake format; medallion architecture (Bronze/Silver/Gold)
Layer 3 — Processing: Azure Databricks (batch + streaming); Azure Synapse Analytics (SQL analytics)
Layer 4 — AI/ML: Azure Machine Learning (custom models); Azure OpenAI Service (GenAI); Azure Cognitive Services (NLP, vision)
Layer 5 — Serving: Azure API Management (AI model APIs); Power BI (dashboards); Epic API write-back (predictions into Epic workflow)
Layer 6 — Governance: Azure Purview (data catalogue); Microsoft Entra ID (IAM); Azure Policy (compliance)
Estimated annual cost (large IDN): $42-68M cloud + $8-14M management

AWS REFERENCE ARCHITECTURE (ML-first organization):
Layer 1 — Ingestion: AWS Database Migration Service + Kinesis Firehose (streaming HL7)
Layer 2 — Storage: S3 (data lake); AWS HealthLake (FHIR-native store)
Layer 3 — Processing: AWS Glue (ETL); Amazon EMR (Spark for large-scale processing)
Layer 4 — AI/ML: Amazon SageMaker (train, deploy, monitor custom models); Amazon Bedrock (GenAI); Amazon Comprehend Medical (clinical NLP)
Layer 5 — Serving: Amazon API Gateway; QuickSight (BI); Lambda (serverless inference)
Layer 6 — Governance: AWS Lake Formation (data permissions); CloudTrail (audit); Macie (PHI detection in S3)
Estimated annual cost (large IDN): $38-62M cloud + $6-12M management

CLOUD GOVERNANCE FRAMEWORK FOR HEALTHCARE

CLOUD CENTER OF EXCELLENCE (CCoE):
Organizations with formal CCoE: 28%
CCoE typical composition: Cloud Architect (chair), FinOps Manager, Security Architect, Data Engineer, Application Owner representative
CCoE responsibilities: cloud service approval process; reserved instance strategy; tagging governance (cost allocation); security baseline standards; new service review
CCoE ROI: $4.2-8.8M annual savings (FinOps + security + architecture optimization) vs. $0.6-1.2M CCoE operating cost

TAGGING AND COST ALLOCATION:
Health systems with > 90% cloud resources tagged for cost allocation: 34%
Untagged resource cost: impossible to attribute to department or use case
Required tags for healthcare AI: Department, Application, Environment (Prod/Dev/Test), Data Classification (PHI/Non-PHI), Cost Center
Cloud AI cost per use case (tracked by tagging): $18,000-84,000/month per AI use case (highly variable)
AI cost per inference (tagged, tracked): $0.004-0.018 per call (enables ROI measurement per AI transaction)

HEALTHCARE AI MLOPS — CLOUD-NATIVE

MLOPS DEFINITION:
MLOps: practices to deploy and maintain AI models in production reliably and efficiently
Healthcare MLOps requirements: model version control, retraining pipelines, performance monitoring, drift detection, audit trail for regulatory compliance

MLOPS STACK (mature healthcare AI programme):
Model registry: MLflow (open source) or Azure ML registry or SageMaker Model Registry
Experiment tracking: MLflow or Weights & Biases
CI/CD for models: Azure DevOps or GitHub Actions with model validation gates
Model serving: Azure ML endpoints or SageMaker endpoints (auto-scaling)
Monitoring: Evidently AI or Great Expectations for data drift; custom dashboards in Power BI or Grafana
Audit log: immutable audit trail required for regulatory compliance; Azure Monitor or AWS CloudTrail + custom logging

MLOPS MATURITY IN HEALTHCARE:
Level 0 (manual, no MLOps): 44% of health systems deploying AI
Level 1 (basic version control, manual deployment): 34%
Level 2 (CI/CD pipelines, automated testing): 16%
Level 3 (full MLOps, automated retraining, drift detection): 6%
Consequence of Level 0: AI models degrade silently; no detection until clinical outcome changes
Model performance degradation timeline without retraining: 18-24 months before clinically significant degradation
