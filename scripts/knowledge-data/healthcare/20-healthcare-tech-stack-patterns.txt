HEALTHCARE TECHNOLOGY STACK PATTERNS AND AI READINESS
Source: KLAS Research 2025, HIMSS Analytics 2025, AbarVa Technology Assessment Data (340+ health systems), Gartner Healthcare Technology Survey

TECHNOLOGY STACK PATTERNS — OVERVIEW

Healthcare technology stacks have consolidated around four dominant archetypes. The archetype a health system inhabits determines its AI readiness score, migration cost, and the optimal AI entry point. Understanding which pattern a client follows is foundational to any AI strategy advisory engagement.

PATTERN A: EPIC-CENTRIC (37% OF LARGE IDNS)

Architecture profile:
EHR: Epic (Inpatient + Ambulatory + Ancillary)
Operational database: Epic Chronicles (InterSystems IRIS)
Reporting database: Epic Clarity or Epic Caboodle (transitioning)
Analytics: Azure Synapse or Snowflake (receiving Epic Clarity data via ETL)
BI tools: Tableau, Power BI, or Epic Radar/Reporting Workbench
AI infrastructure: Azure OpenAI Service (via Microsoft + Epic partnership) + Epic AI modules
Cloud: Azure primary (Epic partnership mandates Azure for Epic Cloud)

AI READINESS SCORE: 58/100 (medium)
Strengths: tight EHR integration; Epic Cosmos access (265M patient records); Azure OpenAI natively available
Weaknesses: Epic dependency for all data pipelines; Clarity ETL latency (18-24 hours batch); Epic API complexity ($180-320/hour developer cost)
AI entry point: Epic AI modules (PA automation, denial prediction, ambient documentation via DAX) — fastest path to production
Data latency: 18-36 hours (batch ETL); real-time only via HL7 v2 ADT feeds or Epic Subscription
AI programme cost: $4.2-8.8M first use case portfolio; 14-22 months to full production

EXAMPLE STACK (Pattern A — large IDN):
Data ingestion: Epic Chronicles → Epic Clarity (SQL, nightly) → Azure Data Factory → Azure Synapse
Analytics layer: Tableau + Power BI (dual-tool; rationalization opportunity)
ML/AI layer: Azure Machine Learning + Azure OpenAI Service
AI governance: Azure Purview (data catalogue) — deployed at only 22% of Pattern A systems
Key risk: Epic Clarity not fully loaded for 18 months post go-live; AI cannot train until data is complete

PATTERN B: BEST-OF-BREED CLINICAL (28% OF LARGE IDNS)

Architecture profile:
EHR: Epic + multiple ancillary best-of-breed systems (specialized oncology EHR like Varian/Aria, standalone behavioral health EHR, separate long-term care system)
Data: Snowflake or Databricks (preferred over Azure Synapse due to multi-cloud neutral position)
BI: Tableau (primary) + Epic Radar (clinical users)
AI: vendor-specific AI tools (one per clinical domain); no unified AI platform
Cloud: Multi-cloud (AWS primary for data, Azure for Epic-connected workloads)

AI READINESS SCORE: 51/100 (medium)
Strengths: clinical flexibility; best clinical tools for each specialty
Weaknesses: integration complexity (1,840 average HL7 interfaces); data in 8+ source systems; no unified patient view
AI entry point: data unification first (Snowflake or Databricks as integration hub), then multi-use-case AI
Data latency: batch (24-48 hours) for cross-system analytics; real-time only within each system
AI programme cost: $6.8-14M first 18 months (data unification + first AI use case)
Key risk: each vendor's AI tool uses different data model; AI insights contradict each other (no single truth)

PATTERN C: CLOUD-NATIVE EMERGING (12% OF IDNS)

Architecture profile:
EHR: Epic or Oracle Health (cloud-hosted)
Data: Databricks Lakehouse (Delta Lake format; unified batch + streaming)
BI: Databricks SQL + Power BI (or Streamlit for data science dashboards)
AI: Azure OpenAI + Databricks MLflow (end-to-end ML lifecycle management)
Cloud: Azure primary or AWS; single-cloud discipline
Integration: Event-driven (Kafka or Azure Event Hubs); real-time streaming for clinical events

AI READINESS SCORE: 72/100 (high)
Strengths: AI-ready architecture; streaming data for real-time clinical AI; unified lakehouse eliminates ETL silos; fastest time-to-production for new AI use cases
Weaknesses: talent gap (requires ML engineers, data engineers; hard to recruit in healthcare); change management challenges (clinical teams must adapt to data-driven workflows)
AI programme cost: $2.4-4.8M first use case (infrastructure already in place); 6-12 months to production
Key risk: technical architecture leads strategy; use case selection may not be clinically optimal; data science team may not have clinical workflow knowledge

PATTERN D: LEGACY/ON-PREMISE (23% OF IDNS)

Architecture profile:
EHR: MEDITECH (Expanse or legacy CS/Magic), older Epic (pre-2015), Cerner legacy (pre-Oracle)
Data: on-premise SQL Server (most common) or Teradata
BI: Crystal Reports, SSRS, or basic Excel extracts
AI: none (AI deployment technically impossible without platform modernization)
Cloud: none or minimal (email-only Microsoft 365)

AI READINESS SCORE: 28/100 (pre-foundation — lowest)
Strengths: stable, known systems; no migration disruption
Weaknesses: AI deployment impossible; EHR increasingly unsupported; security vulnerability growing; unable to meet CMS FHIR mandates; clinical quality constraints without AI

KEY RISKS:
Platform EOL: Genome Pattern F003 — MEDITECH CS/Magic not supported post-2026; older Cerner legacy approaching EOL; forces crisis migration with 38-47% cost premium
Security risk: on-premise systems with legacy OS (Windows Server 2012, 2016) are common ransomware targets
CMS FHIR compliance risk: cannot meet 2026 PA API mandate without EHR modernization
Competitive risk: unable to recruit physicians who expect modern documentation tools (ambient AI, MyChart)
AI programme cost: $18-38M platform modernization required before any AI; 2-4 year timeline

ORGANIZATIONS IN PATTERN D (examples by type):
Community hospitals with MEDITECH CS: 41% of <200-bed hospitals
Rural health systems still on Cerner legacy: 12%
Long-term care and post-acute (PointClickCare, MatrixCare): different AI readiness path
Critical access hospitals: 62% are Pattern D

INTEGRATION ARCHITECTURE BENCHMARKS

HL7 V2 INTERFACE VOLUME:
Average number of active HL7 v2 interfaces per large health system: 1,840
Most common interface types: ADT (Admit/Discharge/Transfer), ORM (orders), ORU (results), SIU (scheduling), DFT (charges)
Interface engine market share: Rhapsody/Rhapsody Cloud (32%), Mirth Connect (28%), InterSystems HealthShare (22%), Cloverleaf (12%), other (6%)
Annual interface maintenance cost: $0.8-1.4M per $1B revenue
Interface failure rate (downtime per interface per year): 4.2 events average; each costs 2-8 hours of analyst time

FHIR INTERFACE GROWTH:
Active FHIR integrations per large health system: 94 average
FHIR interface growth rate: 38% per year
FHIR replacing HL7 v2: estimated 2032 for 50% replacement; HL7 v2 will persist in parallel
API-first architecture adoption (no HL7 v2 for new integrations): 22% of health systems (progressive)

MIDDLEWARE AND INTEGRATION PLATFORMS:
MuleSoft (Salesforce): 18% of large health systems; enterprise integration platform
Azure Integration Services: 24% (growing; natural for Epic/Azure environments)
AWS EventBridge: 14% (growing in AWS-primary systems)
Rhapsody Cloud: 22% (moving to cloud-native from on-premise)
InterSystems HealthShare: 18% (preferred for complex clinical data routing + FHIR)

DATA PIPELINE MATURITY

PIPELINE TYPES BY PREVALENCE:
Batch ETL only (18-36 hour latency): 44%
Hybrid (batch + limited streaming for critical events): 38%
Real-time streaming (< 60 second latency, Kafka/Event Hubs): 18%

LATENCY IMPACT ON AI USE CASES:
Batch-only systems (44%): can deploy — coding AI, readmission prediction, scheduling AI, revenue cycle AI; CANNOT deploy — sepsis early warning, ED capacity, OR real-time scheduling
Hybrid systems (38%): can deploy most AI; real-time for high-priority clinical events only
Full streaming (18%): all AI use cases available; highest competitive AI capability

DATA QUALITY SLA ACHIEVEMENT:
Organizations that meet internal data quality SLAs: 62%
Organizations with no data quality SLA defined: 38%
Average data quality score (AbarVa 0-100): 54 (below threshold for reliable AI)
Data quality improvement timeline with dedicated programme: 12-18 months to reach 70+
Data quality investment required: $1.2-2.8M for large health system (data cleansing, deduplication, governance tools)

AI TOOL ECOSYSTEM BY PATTERN

PATTERN A (Epic-centric) PREFERRED AI STACK:
RCM AI: Waystar AI, Optum360, Epic PA module
Clinical AI: Epic Deterioration Index (sepsis), Nuance DAX (ambient), Epic scheduling AI
Population health: Innovaccer (integrates with Epic via Orchard)
Cloud AI: Azure OpenAI Service (GenAI), Azure ML (custom models)
BI: Power BI (Microsoft ecosystem alignment) or Tableau
Estimated annual AI platform spend: $4.2-8.8M

PATTERN B (Best-of-breed) PREFERRED AI STACK:
Data unification: Snowflake or Databricks (unifies 8+ source systems)
RCM AI: Waystar AI (vendor-neutral)
Clinical AI: specialty-specific (Viz.ai for imaging, Epic EDI for sepsis, Nuance DAX for documentation)
Population health: Arcadia or Health Catalyst (multi-system integration strength)
Cloud AI: AWS Bedrock or Azure OpenAI (depends on primary cloud)
Estimated annual AI platform spend: $6.4-12.8M (higher due to integration complexity)

PATTERN C (Cloud-native) PREFERRED AI STACK:
Data platform: Databricks (Unity Catalog + MLflow + Delta Live Tables)
ML platform: Databricks ML + Azure ML or SageMaker
GenAI: Azure OpenAI or AWS Bedrock (depends on cloud primary)
Clinical AI: custom models trained on unified lakehouse data
BI: Databricks SQL + Power BI
Estimated annual AI platform spend: $3.2-6.4M (lower due to unified platform; no redundant tools)

PATTERN D (Legacy) ROADMAP TO AI:
Year 1: EHR modernization planning; vendor selection; FHIR readiness assessment
Year 2-3: EHR implementation (MEDITECH Expanse, Epic, or Oracle); data warehouse deployment
Year 3-4: First AI use case (coding AI + scheduling AI — lowest data requirement)
Year 4-5: Clinical AI deployment as data matures
Total investment before first meaningful AI ROI: $18-38M; 3-4 years

GENOME PATTERN F003 — PLATFORM EOL:
Average number of platforms within 18 months of end-of-life (per large health system): 3.2
Unplanned migration cost premium: 38-47% above planned
Average time from EOL identification to migration initiation (reactive systems): 14 months
Time from EOL to forced migration (vendor drops support): 6-18 months additional
Revenue impact of clinical system downtime during unplanned migration: $380,000-840,000 per day
Best practice: maintain a platform lifecycle register; audit every system annually; plan migrations 24-36 months ahead

DATA ARCHITECTURE PATTERNS FOR AI

LAKEHOUSE PATTERN (BEST PRACTICE 2025):
Single platform for storage + compute + ML: Databricks (open source Delta Lake) or Microsoft Fabric (OneLake)
Benefits: eliminates ETL between data lake and data warehouse; one metadata layer; ML runs where data lives
Healthcare adoption: 18% of health systems have a lakehouse architecture (growing from 8% in 2022)
Deployment timeline: 12-18 months to replace legacy DW with lakehouse
Cost: $2.8-5.4M migration + $0.8-1.4M/year operation
AI benefit: reduces time-to-production for new AI models from 8 months (legacy ETL) to 6 weeks (lakehouse)

MEDALLION ARCHITECTURE IN HEALTHCARE:
Bronze layer: raw data from source systems (Epic HL7, claims, SDOH, lab feeds)
Silver layer: cleaned, deduplicated, standardized (OMOP CDM or FHIR-aligned)
Gold layer: curated datasets for specific AI use cases (e.g., readmission model features, sepsis training data)
Organizations using formal medallion architecture: 12%
Organizations with informal gold/silver concept: 34%

DATA MESH IN HEALTHCARE:
Data mesh (decentralized data ownership by clinical domain): 8% (very early)
Data mesh requires: strong data governance, distributed engineering teams, mature API culture
Not recommended for Pattern D organizations; best fit for Pattern C or advanced Pattern A

GENOME FAILURE PATTERNS IN TECH STACK

F003 — Platform EOL unplanned: 41% of community hospitals have clinical systems within 18 months of EOL; 38-47% cost premium when forced migration occurs; AI deployment blocked during migration
F019 — Data fragmentation (no unified data layer): 68% of health systems with 6+ source systems cannot build cross-domain AI models; requires data unification investment before AI
F027 — ERP data disconnected from EHR data: financial + supply chain data (Lawson, Workday, Oracle ERP) in separate silo from clinical data (Epic); AI models that need both (supply chain optimization, physician compensation) are blocked
F041 — AI tools purchased that require architecture not in place: 44% of AI tools purchased require streaming or real-time data; health system has batch-only architecture; tools deployed but cannot deliver real-time value
F034 — No AI readiness baseline before programme start: organizations that do not assess their technology stack readiness before committing to AI timelines consistently miss deadlines and overspend on data remediation
F058 — Shadow IT AI tools proliferating outside governance: 91% of health systems have employees deploying unauthorized AI tools; creates security, compliance, and data quality risks that undermine the governed AI programme
