PRIOR AUTHORIZATION — MARKET CONTEXT

Prior authorization is the single highest-ROI AI use case in healthcare revenue cycle management. PA costs providers $11-25B annually in administrative burden. Payers issue 900M+ PA requests annually in the US. CMS is mandating real-time PA by January 2026. The window for proactive AI adoption is closing — health systems that do not automate by 2025 will face compliance exposure and revenue loss simultaneously.

CMS MANDATE — REAL-TIME PRIOR AUTHORIZATION BY 2026

CMS Interoperability and Prior Authorization Final Rule (CMS-0057-F):
- Effective dates: January 1, 2026 (payers must implement); January 1, 2027 (full enforcement)
- Applies to: Medicare Advantage, Medicaid managed care, CHIP, Federal Employees Health Benefits, Marketplace plans
- Key requirements:
  1. Real-time PA decisions for routine requests using FHIR APIs
  2. 72-hour turnaround for urgent PA requests (down from current 14-day max)
  3. 7-calendar-day turnaround for standard non-urgent requests
  4. Payer FHIR API mandated using HL7 FHIR Da Vinci Prior Authorization Support (PAS) IG
  5. Denial reason documentation required in structured form
  6. PA requirements publicly posted via FHIR API so EHRs can embed PA checking
- Traditional Medicare: already exempt from most PA; CMS expanding exemptions for MA to match FFS

FHIR DA VINCI PA STANDARDS

HL7 FHIR Da Vinci Prior Authorization Support (PAS) Implementation Guide:
- Standard for provider-to-payer PA transactions using FHIR R4
- CDS Hooks: embeds real-time PA checking into EHR clinical workflow at point of order
- Coverage Requirements Discovery (CRD): provider queries payer API at order creation; payer returns PA requirement and any auto-approval
- Documentation Templates and Rules (DTR): structured data collection for PA documentation using FHIR Questionnaire
- EHRs with CRD/DTR implemented: Epic (live), Oracle Health (pilot), MEDITECH (in development)

GENOME FAILURE PATTERNS IN PRIOR AUTH

F011 — PA vendor SLA not enforced: 74% of PA automation contracts underperform against committed automation rate; avg 6.2 quarters before health system acts
F019 — Clinical documentation not structured (free text): PA AI requires structured clinical data; free-text heavy documentation reduces AI automation rate from 68% to 38%
F027 — EHR and PA workflow disconnected: when PA workflow is separate from ordering workflow, clinicians work around the system; 44% of PA requests bypass AI tools
F034 — No baseline PA metrics at programme start: without measuring PA volume, approval rate, denial rate, and cycle time on Day 0, ROI cannot be demonstrated; vendor claims unprovable

PRIOR AUTH AUTOMATION — IMPLEMENTATION GUIDE

PHASE 1 — ASSESSMENT AND BASELINE (Weeks 1-8):
PA volume audit: count all PA requests by specialty, payer, service type; identify top 20 payer-service combinations that represent 80% of PA burden
Manual process mapping: document current workflow; identify who touches each PA request and how many times
Baseline metrics (Day 0 must-lock): PA volume per week, PA cycle time (days), PA approval rate (%), PA denial rate by payer, staff FTE dedicated to PA, annual PA cost (FTE + vendor + overhead)
Technology assessment: which EHR modules are in place? Is FHIR API available? Which payers have electronic PA portals?
Payer prioritization: rank payers by PA volume x denial rate x automation feasibility

PHASE 2 — VENDOR SELECTION AND CONTRACTING (Weeks 8-16):
Issue RFP to: Cohere Health, Waystar, Olive, nThrive PAi, Availity
Key evaluation criteria: payer connection library (does vendor connect to YOUR specific payer mix?), automation rate achieved at comparable reference sites, integration approach with your EHR, cost model (per-PA fee or flat), SLA definition and penalties
Contract must-haves: specific automation rate commitment (not a range); denial rate reduction commitment; measured at 6 months and 12 months; penalty clause of $X per month below threshold; termination right if misses 2 consecutive quarters
Avoid: vendors who will not commit to specific metrics; vendors with no reference sites on your EHR

PHASE 3 — IMPLEMENTATION (Months 4-10):
Technical integration: EHR-to-PA-platform integration (Epic FHIR API or HL7); payer connection testing; go-live testing with high-volume, lower-risk payers first
Workflow redesign: PA request must be triggered at time of order in EHR (not after scheduling); move PA work to pre-service period (before patient arrives)
Staff training: PA coordinators train on exception-handling (AI handles routine; humans handle exceptions and peer-to-peer reviews)
Go-live: phased by payer; start with commercial payers (higher automation rate); add Medicare Advantage payers in months 6-9
Monitoring: weekly dashboard of automation rate, approval rate, denial rate, cycle time by payer

PHASE 4 — OPTIMIZATION AND SCALE (Months 10-24):
Model retraining: quarterly retraining with new approved/denied cases; automation rate improves 8-12pp per retraining cycle
FHIR Da Vinci integration: add CRD/DTR as payers come live with FHIR APIs; enables real-time PA checking at point of order
Gold carding identification: AI flags physicians with > 95% 24-month approval rate; submit gold carding requests to payers with legislation
Peer-to-peer AI support: AI generates clinical summary and evidence-based talking points for peer-to-peer review calls; improves overturn rate from 81% to 91%
