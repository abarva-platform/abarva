01

What is a Strategic Move?

A Strategic Move is a phase-gated transformation program — a structured way to take any AI or operational initiative from a one-line hypothesis all the way through to a handed-off delivery.

Every Move has exactly the same anatomy: five phases (P1–P5), a quality gate at the end of each phase that must be cleared before you can advance, and a set of consulting-grade deliverables generated at each phase. The whole journey runs inside the Strategic Moves surface. When a Move completes P5, it transitions automatically into Control Tower for ongoing execution tracking.

💬
One voice: Nexus
All chat on the Strategic Moves surface goes to Nexus, your front agent. Behind it are 12 specialist agents handling gate enforcement, evidence indexing, document versioning, and more — you never interact with them directly. Nexus sounds like one coherent system; the specialisation is invisible.

The Move anatomy at a glance

P0 ✏️ Originate 7-field scaffold, Nexus-guided chat
P1 📋 Charter Program charter + stakeholder map
P2 🔍 Discover As-is assessment, root cause
P3 🎯 Design Target state + solution architecture
P4 📊 Roadmap Execution plan + business case
P5 🚀 Mobilize Handoff package → Tower

03

Before you start

Have these four things ready before opening the origination screen. They're the minimum required to create a Move — Nexus will ask about all of them.

  • The bet / outcome What are you trying to achieve? One clear sentence. Not a project name; an outcome with direction and magnitude. e.g. "Reduce contact center handle time by 30% using AI-assisted routing."
  • An executive sponsor Name and title. Without a sponsor, the Move can't advance past P1 (the charter gate requires sponsor sign-off as a hard criterion). e.g. "Sarah Chen, Chief Operations Officer"
  • A scope boundary What's explicitly in and what's out? Scope creep is a primary failure mode. Nexus will push you to be specific. "All of customer service" is not a scope. e.g. "In scope: inbound routing layer. Out of scope: agent training, CRM changes."
  • A rough value hypothesis What's the magnitude of impact? Doesn't need to be a full business case yet — a directional range is enough. e.g. "$2–4M annual cost avoidance if handle time targets are met."
✓
You don't need everything upfront
The three optional enrichment fields — evidence family, value hypothesis seed, and foundation readiness — are filled through conversation with Nexus. You don't need to prepare them in advance. Nexus will ask targeted follow-up questions during origination.

07

Understanding gates

Every phase ends with a quality gate. Gates are not bureaucratic checkboxes — they're the mechanism that ensures each phase has genuine outputs before implementation begins.

Gate status: three states

🔒
Pending
Phase hasn't started or not all hard criteria have been addressed yet. Advance button is locked.
⚠️
Open
Phase is in progress. Some criteria met, some still outstanding. Advance button shows which criteria are blocking.
✅
Cleared
All hard criteria met. Advance button is active. Soft criteria may still be advisory warnings.

Hard vs. soft criteria

Hard criteria — blocking, must be met
🚫Gate cannot clear until these are satisfied
🚫Advance button is locked if any hard criterion is open
📋Examples: named sponsor, scope boundary, gate document generated
📋Nexus tracks these automatically from your inputs
Soft criteria — advisory, visible to reviewers
⚠️Gate can clear even with open soft criteria
⚠️Shown as advisory warnings in the gate view
📋Examples: stakeholder review done, technical sign-off obtained
📋Appear in the evidence trail viewed by Tower
⚠️
Gates cannot self-approve
In the current pilot configuration, any user can approve their own gate. In production, only admin or Maestro-role users will be able to approve. Gate sign-off is recorded in the audit trail — Nexus (the AI) cannot approve a gate on your behalf.
08

Generating deliverables

Every phase generates consulting-grade documents — charters, assessments, roadmaps, financial models, and more. All documents are generated on demand from the Generate Deliverables tab in the phase canvas.

⚠️
Generate before you download
Download links in the Evidence Hub only appear after a document has been generated. If a document shows "not generated," go back to the phase workspace, open the Generate tab, and generate it first.

How to generate a deliverable

1
Navigate to the phase workspace
Open the Move and click the phase (e.g. P2) in the phase rail at the top.
/strategic-moves/{id}/phase/2
2
Click the "Generate Deliverables" tab in the canvas
The tab is in the right-hand phase canvas. It shows all documents available for this phase with their current status.
3
Select the document you want and click Generate
Each document shows its format (HTML preview + Word download, or Excel for financial models). Gate artifacts are marked with a green GATE chip.
4
Wait for generation (typically 10–30 seconds)
Nexus assembles the document from your scaffold data, phase inputs, and chat history. Complex documents like the Business Case or Financial Model may take longer.
5
Preview the HTML version or download Word / Excel
HTML is for review in-browser. Word is for editing and sharing externally. Excel is for the Financial Model (5 sheets). All versions are linked from the Evidence Hub.

What each format means

HTML
Read-only in-browser preview. Use for reviewing, sharing links internally, or presenting in a meeting.
Word (.docx)
Editable document for external sharing, client delivery, or stakeholder sign-off. All narrative documents.
Excel (.xlsx)
The P4 Financial Model only. 5 sheets: assumptions, 3-year P&L projection, NPV/IRR, sensitivity analysis, and payback curve.

Uploading supporting evidence

You can upload supporting files directly to the Evidence Hub — or attach them in the Nexus chat with the paperclip icon. Uploaded files are indexed by the evidence specialist and attached to the relevant phase. Supported formats: PDF, Word, Excel, CSV, PowerPoint.

10

Do's and don'ts

The most common mistakes new users make — and how to avoid them.

✓ Do
Talk to Nexus like a colleague describing a situation.
"We're trying to cut call handle time by 30%, CFO is sponsor, scope is just the routing layer" — fills three fields in one message.
✗ Don't
Try to fill scaffold fields manually, one at a time.
The scaffold panel is read-only — it updates from what Nexus extracts. Describe the program in chat.
✓ Do
Use the P2 Continue/Discontinue decision explicitly.
If diagnosis reveals a fundamental blocker, say "Nexus, record a Discontinue decision for this Move with rationale: [reason]."
✗ Don't
Leave a Move open indefinitely with no progress.
Stale Moves in P1 or P2 with no gate advancement in 30+ days surface in Control Tower as portfolio risk signals.
✓ Do
Generate deliverables before presenting or distributing.
Regenerate after major chat updates — document content is assembled at generation time from your latest inputs.
✗ Don't
Skip the scope boundary because "everyone knows what's in scope."
Scope disputes are the #1 cause of program failure. Document it explicitly even if it feels obvious.
✓ Do
Upload supporting data files during P2 via the paperclip.
Nexus can parse call logs, ops reports, and financial data to build the Current State Assessment from real evidence, not assumptions.
✗ Don't
Wait until P4 to check the Financial Model assumptions.
The value hypothesis seed from origination seeds the model. Enter a realistic range upfront so P4 refinement is a calibration, not a rebuild.
💡
Getting the most from Nexus
Nexus works best when you give it context, not just commands. Instead of "generate the charter," try "generate the charter — the sponsor is Sarah Chen (COO), scope is inbound routing only, and the program needs to be completed before our legacy routing contract expires in Q3." Richer context produces better documents.
