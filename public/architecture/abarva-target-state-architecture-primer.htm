Internal Product Team Primer · Target-State Architecture

AbarVa is a tenant-grounded decision OS, not a generic AI wrapper.

This document orients new developers to the full AbarVa architecture: the executive product surfaces, the agent and context-broker spine, the Azure private data lane, the data model, the operating controls, and the engineering standards required to build a leading enterprise SaaS platform without weakening tenant isolation or auditability.

Runtime
Next.js + Azure

Next.js app served by Container Apps in the Azure lab; Vercel remains a SaaS edge option.

Data Plane
Postgres

Azure Database for PostgreSQL is the target system of record with tenant-scoped rows and RLS.

Reasoning
Brokered AI

Agents do not read raw stores directly. They reason over typed context bundles.

Operating Model
Auditable

Every change moves through PR, tests, live smoke, evidence docs, and cutover gates.

Architecture Principles

These are the rules that matter more than any individual implementation choice. When in doubt, optimize for tenant trust, evidence quality, and operational repeatability.

1. Tenant context before model reasoning

Agents receive structured context bundles assembled by the broker. The model should never be asked to guess what the tenant data layer could have answered.

2. Postgres is canonical

Relational state, audit rows, context metadata, graph nodes, and graph edges are first-class Postgres records. Search and graph services are projections.

3. Private by default

Customer data lanes use private endpoints, managed identity, Key Vault, RLS, and customer-approved model routing. Public access is the exception, not the norm.

4. No hidden data paths

Application code must not bypass the data-plane seam, context broker, or route-level tenancy checks. If a helper needs data, it should use an adapter or broker contract.

5. Claims must cite evidence

Executive answers should name the tenant facts, evidence chunks, patterns, programs, contracts, or KPI rows behind the recommendation.

6. Automation must leave a trail

Codex and Claude Code can accelerate delivery, but every automated change still requires branch discipline, tests, PR review, live proof, and architecture-log updates.

Target-State Architecture Map

The target architecture is a three-lane Azure SaaS pattern: a public application/control lane, a private tenant data lane, and an intelligence/model lane. The same pattern can run as shared SaaS, dedicated tenant, or customer-private data plane.

Design Canon

Use white or near-white executive surfaces, Georgia headings, DM Sans body copy, black/ghost CTAs, dense Snowflake-style subnavs, and no chat truncation.

Responsive Posture

Desktop is the primary CXO workflow, but mobile must not break. Use stable grids, predictable scroll, and no overlapping controls.

Agent UX

Agent panels must show retrieval/working state, stream clearly, preserve context, and allow pane resizing where workspaces are split.

Middle Tier Design

The middle tier is where AbarVa earns trust. It enforces tenancy, assembles context, chooses tools, routes model calls, records audit evidence, and normalizes data-plane access.

API and Route Handlers

  • Use Next.js App Router route handlers for server APIs.
  • Routes must fail closed on missing tenant, missing auth, or mismatched role.
  • Machine-only endpoints must self-guard with tokens and avoid Clerk HTML redirects when scripts need JSON.
  • Return view models, not raw database rows.

Data-Plane Seam

  • ABARVA_DATA_PLANE=supabase preserves current SaaS behavior.
  • ABARVA_DATA_PLANE=azure-postgres flips read/write adapters to Azure Postgres.
  • Server components and API routes should call adapters, not store clients directly.
  • New modules need a typed read adapter, optional write adapter, and tests for both planes.

AgentContextBroker

The broker is the legal fetch boundary for agent context. It resolves tenant keys, chooses retrieval mode, assembles typed context bundles, injects warnings, and prevents app-tier code from pulling raw corpus/vector/graph data directly.

Model Gateway

The target model lane routes Anthropic/OpenAI/Azure-approved providers through a single gateway. The gateway owns cost, latency, fallback, safety policy, trace IDs, and provider audit rows.

Code Patterns Developers Should Copy

These examples are intentionally small. They show how AbarVa should be extended without breaking tenancy, data-plane portability, agent governance, or Azure cutover readiness.

1. Server Component Page Binding

Resolve tenant server-side, load a view model, render a component. Avoid client-side tenant guessing for protected data.

// Example based on /home
import { getActiveClientRow } from '@/lib/active-client';
import { resolveTenantHome } from '@/components/home/tenant-home-fixtures';

export const dynamic = 'force-dynamic';
export const revalidate = 0;

export default async function HomePage() {
  const activeClient = await getActiveClientRow().catch(() => null);
  const data = resolveTenantHome(activeClient?.key);

  return <TenantHomePage data={data} />;
}

2. Route Handler Tenancy

API routes should fail closed, derive tenant from the session, and return JSON contracts instead of raw database rows.

import { NextResponse } from 'next/server';
import { requireTenancy } from '@/lib/auth/tenancy';
import { selectWriteAdapter } from '@/lib/data-plane/write-adapters';

export async function POST(request: Request) {
  const tenancy = await requireTenancy();
  const body = await request.json();
  const writer = selectWriteAdapter();

  const result = await writer.recordAuditEvent({
    tenantKey: tenancy.clientKey,
    actorId: tenancy.userId,
    action: 'source.event.updated',
    payload: body,
  });

  return NextResponse.json({ ok: result.ok });
}

3. Data-Plane Adapter Selection

The same app code can run on current Supabase-backed SaaS or Azure Postgres by flipping one environment variable.

// src/lib/data-plane/read-adapters/resolveDataPlane.ts
export function resolveDataPlane(raw?: string | null): DataPlane {
  const value = (raw ?? process.env.ABARVA_DATA_PLANE ?? '')
    .trim()
    .toLowerCase();

  return value === 'azure-postgres' ? 'azure-postgres' : 'supabase';
}

4. Agent Retrieval Boundary

Agents should not call search/vector/graph stores directly from UI or API code. The broker assembles the safe context bundle.

const contextBundle = buildSentinelContextBundle({
  tenantKey: brokerTenantKey,
  agentName: 'Sentinel',
  surface: 'intelligence',
  includeGraphNeighborhood: true,
  requestedDomains: [
    'graph_readiness',
    'program_lifecycle',
    'people_org',
    'evidence_provenance',
  ],
});

5. Azure AI Search Tenant Filter

Retrieval projections are useful only if every query pins tenant identity at the choke point.

function buildFilter(tenantKey: string, filters?: TenantContextFilters) {
  const parts = [`tenant_key eq '${escapeOdataLiteral(tenantKey)}'`];

  if (filters?.minConfidence !== undefined) {
    parts.push(`confidence ge ${filters.minConfidence}`);
  }

  return parts.join(' and ');
}

6. Protected Health Endpoint

Machine routes should return JSON and use a token or managed-identity boundary. Do not let Clerk redirect scripts to HTML.

const token = request.headers.get('x-abarva-health-token');
if (!token || token !== process.env.AZURE_CONNECTIVITY_HEALTH_TOKEN) {
  return NextResponse.json({ ok: false, error: 'unauthorized' }, { status: 401 });
}
Copy rule: when adding a feature, find the closest existing page/adapter/route/test pair and copy the boundary shape. Do not introduce a new one-off data path unless the architecture document is updated and tests prove the new boundary.

Day-1 Dataset Load Flow

  1. Client provides approved templates or extracts: org, systems, spend, vendors, KPIs, policies, programs, incidents.
  2. Upload enters Blob or controlled admin upload endpoint.
  3. Sensitive-upload guard classifies the file and quarantines if needed.
  4. Parser normalizes rows into tenant-scoped canonical records.
  5. Chunker creates retrieval chunks with source/evidence metadata.
  6. Backfill projects chunks to Azure AI Search and graph relationships to the graph projection.
  7. Steward/Data Trust shows loaded counts, trust rungs, empty packs, and next best load.

Day-2 Incremental Refresh Flow

  1. Connector or file drop emits Event Grid / Service Bus message with tenant, source, schema version, idempotency key.
  2. Ingestion worker validates schema, checks sensitivity, and writes canonical deltas.
  3. Broker rebuild updates context bundles, search indexes, graph projections, and quality issues.
  4. Audit rows capture who/what/when/source and any quarantine/release decision.
  5. Parallel-run and parity scripts compare row counts, top facts, pattern IDs, and tenant invariants.
Important data posture: PHI and PII are not required for today's product value. The preferred enterprise setup loads business context, metadata, KPIs, policies, vendor economics, and operational telemetry. If PHI/PII appears, it is treated as an exception path: classify, quarantine, audit, and require explicit disposition.

Developer Standards

New developers should treat AbarVa as an enterprise product with a strict architectural seam. The fastest way to create a security incident is to add a convenient direct data path, a hard-coded tenant story, or an untested agent prompt change.

Code Boundaries

  • Use data-plane read/write adapters for app data access.
  • Use AgentContextBroker for agent context.
  • Return view models from routes; transform DB rows at the boundary.
  • Keep tenant-key canonicalization explicit and tested.
  • Do not import vector, graph, or data-room internals from app UI code.

UI Standards

  • Use the existing shell, nav, typography, and component density.
  • Every table/graph must answer a business question.
  • Agent chat should be resizable where it shares a workspace with a canvas.
  • No cross-tenant or cross-industry placeholder copy.
  • No visible feature-explainer text inside the app unless it belongs to Learn.

Data Standards

  • Every tenant-scoped row needs tenant identity.
  • Every import needs source, timestamp, confidence, and lineage where applicable.
  • Use structured parsers for CSV/XLSX/YAML/JSON ingestion.
  • Quarantine suspected sensitive data; do not silently index it.
  • Graph edges are projections from canonical records, not free-floating facts.

Agent Standards

  • Voice doctrine changes require behavior tests.
  • Answers must be calibrated when context is sparse.
  • Recommendations should include dissent or what would change the view.
  • Tool calls must preserve tenant, actor, and surface context.
  • Consistency guards should log caught violations for telemetry.

Database and security Migrations, RLS, tenant isolation probes, seeded synthetic data. Dry-run, SQL regression, rollback/restore path, no real client data mutation without explicit human window.
