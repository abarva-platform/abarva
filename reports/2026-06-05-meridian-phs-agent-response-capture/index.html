17. meridian-cdao / intelligence-ask / Q17: What is the difference between an integration, a source extract, a table, a data product, a dashboard, and a governed metric?

Status: answered · Events: 26

Answer

Here’s how I’d draw the lines, in practical Meridian terms: (1) Integration
A live or scheduled pipe that moves data between systems. Example: HL7/FHIR/flat-file feed from Epic into the EDW; API feed from ERP into cost accounting. It’s about connectivity and movement, not analysis. (2) Source extract
A specific “snapshot” pulled from a source system, usually at a set cadence and grain. Example: daily Clarity encounter extract, monthly GL extract. It’s a file or batch, not yet modeled for broad reuse. (3) Table
Where extracted/ingested data actually lives in the warehouse/lake. A structured set of rows/columns. Tables can be raw (landing), curated (conformed), or mart-level. They’re building blocks, not business answers. (4) Data product
A curated, documented, reusable dataset built around a business need or entity (patients, encounters, providers, cost-per-case, readmissions). It usually bundles multiple tables, logic, and SLAs, with an owner. (5) Dashboard
A visual application (e.g., Power BI/Tableau) that uses data products (or sometimes raw tables) to answer a set of questions for a specific audience, often with interactivity and drill-down. (6) Governed metric
A single defined measure with agreed business logic, owner, and change control. Example: “30‑day all-cause readmission rate,” “risk-adjusted cost per case.” Governed metrics are used inside data products and dashboards so that everyone sees the same number.
