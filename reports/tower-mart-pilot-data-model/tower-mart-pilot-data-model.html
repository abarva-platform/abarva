AbarVa Tower · Pilot Data Model

One Executive Dashboard Mart, Tenant-Specific Rows

Tower Command Center should not fork by tenant. Every tenant flows through the same source-to-facts-to-mart contract; differences are expressed as row counts, evidence coverage, and safe gaps.

Target Contract

Design rule: one `cio_tower` dimensional/read-model contract powers Home/Tower pilot dashboards. Running the governed projection job populates the same mart tables for any tenant.

Shared

Shared

Implemented

Pilot

Mart Tables

Table Grain Role in Executive Dashboard Tenant Behavior
cio_tower.facts canonical metric fact single merge point for V3, telemetry, and derived evidence same columns; tenant-specific source rows
mart_command_center one row per tenant/version headline budget, value, validation, decision question required for rich Command Center render
mart_value_funnel five value stages funding to promised to validated to claimable ladder same five stages, tenant-specific values
mart_program_decision_lanes one row per funded program Fund/Fix/Freeze/Stop posture with gates and evidence row count varies by portfolio
mart_ai_portfolio one row per AI program/tool/candidate AI portfolio matrix, filters, candidate pipeline can be dense; UI caps matrix at top 10 per filter
mart_cxo_actions one row per recommended action board/action queue grouped by owner lane generated from evidence posture, not freeform chat
mart_evidence_lineage one row per displayed fact/source link traceability for numbers and assertions must grow with displayed surface area
mart_required_field_gaps one row per missing/blocking field safe gaps instead of fabricated zeroes pilot differentiator: sparse data is explicit

Pilot Implementation Path

1. Project

Run tenant-specific `project:tower-mart:*:write-job` through the governed ACA operator job.

2. Read Back

Verify `cio_tower.facts` and all seven `mart_*` row families by tenant key.

3. Browser Prove

Sign in per tenant and prove `/tower` renders the shared Command Center, not the safe empty state.

4. Widen Carefully

Keep tenant allowlists until sparse-data behavior is reviewed and pilot owners approve broader rollout.

Guardrails

No fabricated zeroes

Missing budget or evidence emits gaps and safe empty states, not confident-looking dashboard numbers.

No realized value unless gated

Finance validation can be partial; claimable/realized value remains blocked unless evidence gates allow it.

Dense AI stays usable

Bubble matrix renders the top 10 for the current slice; full filtered lists remain available for inspection.
