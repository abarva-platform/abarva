## Part 1 · What this page is

### 1.1 · The front door

Someone hears about AbarVa from an investor, a peer, a piece of content. They type abarva.ai into their browser. What they see in the next 8 seconds determines whether they read further.

The current production homepage is serviceable. This rewrite elevates it to genuinely memorable — editorial character, intellectual seriousness, design precision that signals the product it describes is precise.

### 1.2 · The reader we're writing for

Primary: senior enterprise executive (CIO, CFO, Chief Transformation Officer, CEO of mid-market enterprise)
Secondary: investor evaluating AbarVa pre-pitch
Tertiary: prospective employee

All three benefit from the same tone: intellectually serious, visually refined, compound-value thinking visible.

### 1.3 · The one-sentence positioning

Above all else, the homepage must communicate:

> **AbarVa is enterprise transformation intelligence — the AI-native platform that turns strategic intent into decisions, decisions into programs, and programs into measurable outcomes, at the depth serious transformation actually requires.**

Every section of the page is a proof point for this sentence.

## Part 3 · Design system compliance

The existing AbarVa design system is specific. This rewrite must honor it:

- Georgia serif for display headings and the wordmark
- DM Sans for body text, nav, subheads, and UI
- JetBrains Mono for eyebrows, intelligence names, small labels, and anything resembling code
- Near-black background (#0A0A0B or the existing token)
- Warm off-white for text (#E8E8E8 or the existing token)
- Teal accent (match the wordmark teal)
- No purple gradients anywhere
- No stock photos, no stock illustrations, no stock icons
- No generic UI components (avoid shadcn defaults)

Motion:
- Subtle stagger on hero reveal
- Intersection-observer-triggered subtle entrances for below-fold sections
- Hover states gentle, not bouncy

Texture:
- Consider subtle noise texture on background for depth
- Consider a muted grid or brand-aligned generative visual in hero
- Avoid default flat colors — add atmosphere

## Part 5 · Implementation specs

### 5.1 · Routing

- `/` or `/index` — the homepage

### 5.2 · Component hierarchy

```
<HomePage>
  <MarketingNav />
  <Hero />

  <ThreePlaneArchitecture />
  <TransformationGenome />
  <ProofPoints />
  <WhoWeWorkWith />

  <Footer />

```

### 5.3 · Content management

- Copy stored in a content file (Markdown or TypeScript exports) so Anand can iterate without code changes
- Product list (the 9 intelligences) sourced from a single definition shared with Intelligence Suite detail pages (C2)
- Easy to swap CTAs or update copy

### 5.4 · Responsive

- Mobile-first approach where practical
- Breakpoints: 768px tablet, 1024px desktop, 1440px wide desktop
- Hero typography scales responsively
- 9-product grid: 3 columns desktop → 2 tablet → 1 mobile

### 5.5 · Performance

- Single route, statically generated where possible (Next.js SSG)
- Critical CSS inlined
- Fonts: preload Georgia and DM Sans primary weights
- Images: AVIF/WebP with fallbacks
- Scripts: no third-party analytics crap in the critical path; load analytics deferred

### 5.6 · Accessibility

- Semantic HTML throughout
- Focus states visible and brand-consistent
- Color contrast AA minimum
- Motion respects prefers-reduced-motion
- Heading hierarchy proper (single H1, logical H2/H3)

## Part 6 · Edge cases

### 6.1 · No JavaScript

Page should render and be readable without JS. All text content, navigation, and CTAs functional. Advanced visuals may degrade gracefully.

### 6.2 · Print view

Clean print stylesheet — prints as if a white paper rather than web page.

### 6.3 · Slow network

Skeleton shimmer for lazy-loaded sections. Hero loads first and is fully usable before below-fold content.
