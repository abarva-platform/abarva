# Airline Synthetic Depth Requirements

This package now commits Airline Demo New to the scale expected for a $50B+ airline-style enterprise. The goal is not to create technical noise; it is to make Source, Home, Intelligence, Moves and Tower reason from a realistic operating estate.

## Minimum synthetic scale

- 1,492 applications and platforms across operations control, crew, MRO, station operations, passenger service, digital, revenue management, cargo, ERP, data, security, infrastructure and custom legacy.
- 2,260 integration and middleware paths spanning API, MQ/event, batch/file, ETL/ELT, streaming and mainframe transaction patterns.
- 320 data, analytics and AI products with Teradata-scale EDW, cloud lakehouse, BI, operational marts and governed AI-feature candidates.
- 460 infrastructure components across data centers, private cloud, AWS-style cloud, Azure-style cloud, station edge, mainframe and integration runtimes.
- 118 existing vendor contract records covering MSAs, SOWs, rate cards, cloud commits, managed services, telecom/network, cybersecurity, data platforms and transition support.
- 3,250 relationship rows to reconstruct the graph across applications, data, vendors, contracts, KPIs, service towers and business processes.

## Business-problem framing

The data exists to answer sourcing and transformation questions about operational resilience, cost transparency, transition risk, supplier leverage, value realization and evidence quality. It is not a technical inventory for its own sake.

## Client-collection realism

A real client would not hand-enter every row. The intake pack expects a mix of CMDB export, ITSM export, contract/rate-card files, cloud exports, finance extracts, data catalog extracts and targeted interviews. Claude-assisted ingestion can classify and summarize; AbarVa owns canonical identity, evidence, review state and publication.
