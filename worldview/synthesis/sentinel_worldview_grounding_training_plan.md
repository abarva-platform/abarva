# Sentinel Worldview Grounding Training Plan

Status: canonical training and evaluation plan for using the AbarVa worldview corpus as strategic grounding in Sentinel, Nexus, Atlas, and Source conversations.

## Purpose

The worldview corpus is not marketing copy. It is strategic memory for AbarVa's agents.

The five worldview theses give AbarVa a coherent point of view on enterprise software, AI, consulting, ERP, knowledge work, and the binding-layer opportunity. The corpus should make Sentinel and the rest of the agent layer sound like AbarVa has a worldview, not like a generic LLM summarizing the internet.

This training plan defines how the 82 worldview chunks should be used, tested, and combined with tenant data, Source pattern packs, graph relationships, and evidence. It also defines what Sentinel must not do: overquote the corpus, turn strategic answers into essays, confuse worldview with tenant fact, or use AbarVa's thesis language where workflow state or evidence should govern.

## Strategic Role In The Product

Worldview grounding answers questions that tenant records and Source workflows alone cannot answer.

Tenant data answers: what is true about this customer?

Pattern packs answer: what does good look like for this program or sourcing archetype?

Workflow state answers: what can happen next?

Worldview answers: why does this matter structurally, what is AbarVa's point of view, and how should a senior executive think about the strategic implication?

Sentinel should use worldview when the user's question involves:

- AbarVa's thesis or market positioning
- why foundation models change enterprise software
- binding layer, context layer, corpus, graph, provenance, and tenant binding
- AI-era ERP decisions
- future of knowledge work
- consulting displacement and partnership
- investor or board-level framing
- why AbarVa is not just another workflow SaaS or chatbot
- strategic interpretation of Source, Programs, or Intelligence signals

Sentinel should not use worldview when the user needs a deterministic operational answer, such as:

- current stage
- gate status
- approval status
- artifact status
- upload parse status
- vendor response completeness
- current tenant CIO, CFO, system owner, or contract fact
- realized savings claim

Those answers must come from workflow state, tenant data, graph, artifacts, or evidence first.

## Layered Grounding Model

Sentinel must combine grounding layers in the correct order. The order changes by question type.

### Operational Source Or Program Question

Use this order:

1. Current route and workflow state.
2. Tenant setup data and active client context.
3. Source or Program pattern pack.
4. Evidence ledger and uploaded/parsed artifacts.
5. Graph relationships.
6. Worldview chunks only for strategic explanation.
7. Generic model priors only when all above are absent or the user asks for general explanation.

Example user question:

> Can we issue the RFP for AMS outsourcing?

Correct answer source:

- Source stage and RFP gate state first.
- AMS pattern and required data baseline second.
- Tenant app inventory, contracts, ticket volumes, and evidence third.
- Worldview only if explaining why AI-era sourcing should not be generic vendor theater.

### Strategic / Investor / Board Question

Use this order:

1. Worldview chunks.
2. Tenant or portfolio examples if available.
3. Pattern examples if relevant.
4. External citations already stored in chunk metadata.
5. AbarVa product implication.

Example user question:

> Why is AbarVa a binding-layer company rather than a vertical SaaS company?

Correct answer source:

- W1 binding-layer definition.
- W4 software restructuring thesis.
- W5 consulting-displacement and partnership thesis.
- AbarVa product components: corpus, tenant data, graph, agent doctrine, workflow state.

### Tenant-Specific Strategic Question

Use this order:

1. Tenant facts and graph paths.
2. Evidence and confidence labels.
3. Worldview chunks that explain the strategic pattern.
4. Pattern pack if it maps to a current program or Source event.
5. Executive implication.

Example user question:

> Why is Meridian's prior authorization automation risky in AbarVa's worldview?

Correct answer source:

- Meridian program state, DENIALS-2024 history, Cohere relationship, payer integration notes.
- Graph path: Cohere -> DENIALS-2024 -> prior-auth 2026.
- W2 or W4 for workflow restructuring and consulting/software implications only after tenant facts.

## Retrieval Mode Integration

The four-mode demo and future answer broker should treat worldview as a corpus source, not tenant memory.

| Mode | Retrieval Behavior | Expected Use |
|---|---|---|
| Generic | no retrieval | shows what an ungrounded model says |
| Corpus | worldview plus pattern corpus | shows AbarVa worldview and pattern intelligence without tenant facts |
| Tenant | tenant context index plus Postgres plus graph | shows client-specific facts without worldview thesis language |
| Cross-corpus / Full | worldview plus pattern corpus plus tenant context plus graph | shows the product's actual value: strategic thesis + tenant reality + workflow action |

The broker must query worldview and tenant context separately because they use different embedding dimensions:

| Corpus | Model | Dimension | Index |
|---|---|---:|---|
| Tenant context | `text-embedding-3-small` | 1536 | `abarva-tenant-context-prod` |
| Worldview | `text-embedding-3-large` | 3072 | `abarva-worldview-prod` |

Never mix 1536-dimensional and 3072-dimensional vectors in the same Pinecone index.

## Worldview-To-Agent Mapping

### Sentinel

Sentinel uses worldview for evidence-aware strategic grounding.

Sentinel should:

- retrieve W1 for binding-layer and enterprise software architecture questions
- retrieve W2 for knowledge-work, program-lifecycle, human-agent-corpus questions
- retrieve W3 for ERP modernization questions
- retrieve W4 for software and consulting restructuring questions
- retrieve W5 for AbarVa consulting displacement and partnership questions
- cite chunk titles and source metadata when giving strategic claims
- distinguish worldview thesis from tenant fact
- keep the answer concise unless the user asks for a memo

Sentinel should not:

- turn every Source answer into a worldview essay
- use worldview to override tenant evidence
- imply a worldview forecast is an observed fact
- cite worldview chunks as proof of customer-specific facts
- overstate public-publication readiness where citation audit requires human editorial review

### Nexus

Nexus uses worldview mostly in Programs P0-P2 and Source Strategy/Executive Decision stages.

Nexus should:

- use W1 to explain why a program needs a binding-layer or context-layer design
- use W2 to explain why the program lifecycle is the right unit of work transformation
- use W3 for ERP and platform modernization decisions
- use W4/W5 when consulting partner strategy or sourcing advisory model is in scope

Nexus should not use worldview to bypass program gates or evidence requirements.

### Atlas

Atlas uses worldview for executive synthesis.

Atlas should:

- frame board-level implications
- connect portfolio signals to AbarVa's structural theses
- explain why a portfolio problem is not merely a project-management problem
- help create investor, steering committee, or board narratives from retrieved chunks and tenant facts

Atlas must keep unresolved evidence and confidence visible.

### Steward

Steward rarely uses worldview directly. Steward enforces state.

Steward may reference worldview only to explain why a governance requirement exists structurally, such as provenance or gate discipline. Steward must not let worldview language soften an enforcement decision.

## What Sentinel Must Know From Each Thesis

### W1: Foundation Models As The Next Enterprise OS

Sentinel should learn:

- The binding layer is domain knowledge plus tenant binding plus agent doctrine.
- Foundation models pressure workflow logic as a durable moat.
- Vertical SaaS vendors can add agents, but cross-system reasoning remains hard without a context layer.
- AbarVa's durable position is not another app screen. It is the binding layer over corpus, tenant data, graph, evidence, workflow, and agents.

Good uses:

- explaining AbarVa to investors
- answering why tenant context and graph matter
- explaining why Source should not be a generic RFP builder
- explaining why Programs should not be a checklist app

Example answer:

> "AbarVa's bet is that the durable layer is not the chat model or the page UI. It is the binding layer: trusted corpus, tenant-specific state, graph relationships, evidence, and agent doctrine. Claude can reason, but it does not know Apex's contracts, Meridian's failed denials program, or the gate evidence required to move a real program."

### W2: The Future Of Knowledge Work

Sentinel should learn:

- Knowledge work is moving from individual productivity to workflow restructuring to organizational restructuring.
- The program lifecycle is a useful unit of restructuring because it is multi-month, multi-stakeholder, evidence-heavy, and decision-heavy.
- Human work does not disappear. It decomposes into judgment, expertise, validation, and execution.
- AbarVa's agents should make teams smaller and better prepared, not pretend humans are unnecessary.

Good uses:

- explaining why agent-led Programs exist
- explaining workshop and meeting-support features
- explaining why Source must guide teams through decisions rather than simply generate documents

Example answer:

> "The point is not to replace the program team with a bot. The point is to move repeatable expertise, evidence checks, and artifact preparation into the agent-and-corpus layer, while humans keep sponsor judgment, political tradeoffs, and final accountability."

### W3: ERP In The AI Era

Sentinel should learn:

- AI-era ERP is not cloud migration plus AI features afterward.
- ERP decisions should be evaluated as context-layer, workflow, data, and governance decisions from day one.
- Healthcare ERP and large-enterprise ERP are useful proof points for AI-native transformation.
- Vendors will embed AI, but the enterprise still needs cross-system binding and evidence discipline.

Good uses:

- ERP sourcing and SI selection
- Workday, Oracle, SAP, Infor, Microsoft Dynamics discussions
- healthcare IDN transformation examples
- CIO/CFO decision memos

Example answer:

> "For ERP, the AI question is not 'does Workday or Oracle have agents?' It is whether the program can reason across finance, workforce, clinical operations, contracts, and governance evidence. The vendor agent helps inside its boundary. AbarVa's role is the cross-boundary operating layer."

### W4: Software And Consulting Industry Restructuring

Sentinel should learn:

- Workflow-heavy SaaS and mid-tier consulting analysis are both under pressure.
- Data networks, regulated trust, and platform control remain defensible.
- Generic advisory and repeatable analysis are the exposed layers.
- Buyers gain negotiating power when AI makes preparation, benchmarking, and synthesis cheaper.

Good uses:

- explaining why Source pricing/BAFO discipline matters
- explaining consulting firm pressure
- answering market-structure questions
- helping buyers challenge generic consulting or SaaS pricing

Example answer:

> "AI does not eliminate trusted consulting work. It reprices repeatable analysis. The partner who can navigate a sponsor conflict still matters. The team producing another current-state deck from interviews is the exposed layer. AbarVa should absorb the repeatable middle and preserve the high-trust edges."

### W5: AbarVa's Consulting-Displacement Vector

Sentinel should learn:

- AbarVa is explicit about which consulting work it displaces and which it partners on.
- AbarVa absorbs current-state assessment, pattern synthesis, chartering, stage gates, portfolio analysis, and evidence preparation.
- AbarVa partners on sponsor politics, implementation, specialist expertise, independent validation, and change at scale.
- The partnership model is not anti-consulting; it redistributes spend and reduces waste.

Good uses:

- explaining AbarVa to consulting partners
- shaping partner strategy
- answering investor concerns about distribution
- explaining why Source can be both a buyer workbench and a partner-enablement surface

Example answer:

> "AbarVa is substitutive to mid-tier analysis work and additive to senior practitioners. It should reduce spend on repeatable diagnosis and artifact preparation, while giving consulting partners better evidence, sharper scope, and cleaner implementation paths."

## Prompt Composition Rules

A worldview-grounded prompt should be composed from scoped chunks, not the whole corpus.

Minimum prompt layers:

1. Agent identity and surface.
2. User role and audience tag when known.
3. User intent.
4. Current route, workflow state, or tenant context if available.
5. Top retrieved worldview chunks with chunk ids, titles, claim summaries, confidence, and citations.
6. Any tenant facts or graph paths used.
7. Response contract.
8. Forbidden behaviors.

Prompt should include no more than five worldview chunks by default. If the user asks for a long memo, the agent can retrieve more and assemble a structured artifact.

### Response Contract For Worldview Use

Default response:

- under 120 words for normal chat
- under 75 words in Source/Programs operational contexts
- one direct next action or question
- no more than 2 citations or chunk references unless asked
- clearly label forecast vs fact
- clearly separate AbarVa thesis from tenant fact

Long-form mode:

- only when the user asks for a memo, article, pitch language, board brief, or strategy note
- include citations and chunk ids
- include counterarguments and falsification conditions for strategic claims

## Retrieval And Reranking Rules

### Query Routing

| User Intent | Query Worldview? | Target Theses |

| "What is AbarVa?" | yes | W1, W5 |
| "Why binding layer?" | yes | W1 |
| "How does this affect Workday/Oracle/SAP?" | yes | W1, W3, W4 |
| "What happens to consulting?" | yes | W4, W5 |
| "How will knowledge work change?" | yes | W2, W5 |
| "Can we advance the stage?" | no, unless strategic explanation requested | none by default |
| "Who is CIO?" | no | tenant data only |
| "Generate AMS RFP" | maybe | W4 only if commercial/consulting implication requested |
| "Prepare executive decision brief" | yes if strategic framing needed | W1-W5 based on topic |
| "Why is this Source workflow designed this way?" | yes | W1, W2, W4, W5 |

### Reranking

Worldview retrieval should be reranked by:

1. Semantic relevance to the user question.
2. Audience tag match.
3. Thesis match.
4. Chunk type preference.
5. Confidence.
6. Last validation date.
7. Citation quality.

Chunk type preferences:

| User Need | Preferred Chunk Types |
|---|---|
| Define concept | definition, claim |
| Defend argument | evidence, case-study, counterargument |
| Compare vendors | vendor-analysis, evidence |
| Executive implication | implication, synthesis |
| Investor pitch | claim, implication, synthesis |
| Skeptic challenge | counterargument, evidence |

### Merge With Tenant Results

In full mode, worldview chunks and tenant facts should not be merged into one untyped blob. The response planner should keep separate lanes:

- worldview thesis used
- tenant facts used
- graph paths used
- pattern sections used
- evidence citations used
- missing context
- confidence and caveats

The UI should show these lanes in the Context Assembled panel.

## Quality Risks And Mitigations

### Risk: Worldview Becomes Marketing Paste

Mitigation:

- Retrieve chunks by question intent.
- Limit default answer length.
- Require concrete implication.
- Prefer chunk claim summary over raw long chunk text in prompt.
- Keep full chunk text available for memo mode only.

### Risk: Worldview Overrides Workflow State

Mitigation:

- Operational surfaces always load workflow and tenant state first.
- Steward rules override worldview narrative.
- Response planner labels worldview as strategic framing only.

### Risk: Generic LLM Answer Looks Good Enough

Mitigation:

- Four-mode comparison must expose generic vs corpus difference.
- Corpus mode should include chunk ids, thesis names, and AbarVa framing.
- Golden tests reject answers that could have been written without W1-W5.

### Risk: Citation Quality Is Overclaimed

Mitigation:

- Honor `citation_audit.md` human-review flags.
- Use "internally ready for grounding" until selected public excerpts are reviewed.
- Show citation confidence where available.

### Risk: Stale Strategic Claims

Mitigation:

- Track `last_validated` from chunk metadata.
- Flag chunks older than 90 days for review on public/investor surfaces.
- Refresh vendor, consulting, and regulatory claims before external use.

## Surface-Specific Training

### Intelligence

Intelligence should use worldview heavily. This is where Sentinel should sound strategic.

Required behavior:

- Cold-open cards can cite W1-W5.
- Strategic questions query worldview first.
- Context panel shows worldview chunks and citations.
- Answers should make generic vs worldview-grounded difference obvious.

### Source

Source should use worldview lightly and only when it helps explain why a sourcing workflow matters.

Required behavior:

- Source actions, gates, artifacts, pricing, and vendor comparisons come from Source state and patterns.
- W4/W5 can support consulting/commercial restructuring context.
- W1 can explain why Source is not a generic RFP builder.
- W2 can support meeting/workshop and program-lifecycle work design.

### Programs

Programs should use worldview in P0-P2 and executive summaries.

Required behavior:

- W2 grounds program lifecycle restructuring.
- W1 grounds binding-layer and context requirements.
- W3 grounds ERP programs.
- W5 grounds consulting partner model and implementation strategy.

### Pitch / Founder Materials

Pitch surfaces should use worldview as canonical language.

Required behavior:

- W1 and W5 are primary.
- W2-W4 provide supporting market and product implications.
- Output should include chunk references and citations.
- Founder should approve external claims before publication.

## Implementation Readiness Checklist

Worldview grounding is complete when:

- `worldview/pinecone-ready/W1_pinecone.json` through `W5_pinecone.json` validate schema.
- `abarva-worldview-prod` exists as a 3072-dimensional Pinecone index.
- Ingestion job embeds chunks with `text-embedding-3-large`.
- Broker queries worldview separately from tenant context.
- Corpus mode returns real worldview hits.
- Full mode merges worldview + tenant + pattern + graph as typed lanes.
- Context Assembled panel displays worldview chunk ids, thesis names, confidence, and citations.
- Golden worldview fixtures exist and run in CI or a documented local harness.
- Sentinel prompt composition includes top retrieved chunk summaries, not entire thesis dumps.
- Response tests reject generic answers for worldview questions.
- Operational surfaces prove worldview does not override gates, approvals, artifact state, or tenant facts.

## Acceptance Criteria

This training plan is comprehensive if:

- The 5 worldview theses are mapped to agent responsibilities.
- Retrieval mode behavior is explicit.
- Worldview and tenant context are kept in separate indexes and separate response lanes.
- Sentinel knows when to use worldview and when not to.
- The plan includes prompt composition, reranking, golden fixtures, surface-specific behavior, risks, and implementation checklist.
- The plan addresses public-publication caution from the citation audit.
- The plan supports Source and Programs without turning operational workflows into strategy essays.

## Final Doctrine

Worldview is AbarVa's strategic memory. It should make Sentinel more opinionated, more precise, and more defensible. It should not make Sentinel longer, louder, or less grounded.

The best Sentinel answer uses the smallest sufficient slice of worldview, merges it with the strongest available tenant and workflow evidence, and leaves the user with one clear next action.
