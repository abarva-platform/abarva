## Summary

### Headline finding (read first)

**The deployed surface is currently mis-rendering at runtime because most of the design tokens it references are not defined in the maestro bundle.** `StrategicMoves.module.css` references `--canon-border`, `--canon-border-strong`, `--canon-bg-cream`, `--canon-teal`, `--canon-teal-dark`, `--canon-teal-light`, `--canon-amber`, `--canon-amber-light`, `--canon-red`, `--canon-red-light`, `--canon-gray-300/500/600/700/800/900`, `--abarva-ink-black`, `--abarva-signal-blue`, `--abarva-serif`, `--abarva-sans`, and `--abarva-mono`.

`src/app/(maestro)/layout.tsx` only imports `globals.css`. Neither `src/lib/shell/brand-tokens.css` nor `src/styles/abarva-canon.css` is loaded on these routes, and `globals.css` defines none of the above. The properties resolve to their initial values, so:

- `border` rules compress to `1px solid initial` (browser draws nothing or a thin black line).
- Background colors (`--canon-bg-cream`, `--canon-teal-light`, etc.) fall back to `transparent` / `currentColor`, leaving cards bare.
- `font-family: var(--abarva-serif)` falls back to the parent's body font, so Fraunces never appears.
- Status chips have no fill or border.

This means **a great deal of what the audit calls a "wrong color" or "missing border" below is actually a token-resolution failure compounding on top of design divergence**. Phase B must (a) ensure the canonical tokens from `docs/design/strategic-moves/tokens.css` (already canonical per `tokens.css`) are loaded on the Strategic Moves routes, then (b) fix the per-component divergences listed here. Both are required; neither alone is sufficient.

### Patterns repeated across components

- **Token misuse:** `--canon-*` and `--abarva-*` referenced without the tokens being loaded in this route group. Affects every file in `src/components/strategic-moves/`.
- **Hard-coded raw colors and font sizes:** `#0d1f47`, `#f6f2e8`, `#2e6de0`, `#9b6a1a`, `#8b6830`, `#12264d`, `#36a883`, `#c88933`, `#ad3c3c`, `#ebe7df`, etc. Even after tokens are loaded, these hex values must move to tokens or be removed.
- **Eyebrow-color inconsistency:** Eyebrows are tinted variously `#9b6a1a`, `#716754`, `#8b6830`, `#69a9ff`, gold-ish — none of which match the canonical eyebrow color rules from `tokens.css` (`--abarva-stone` / `--abarva-signal-blue` / `--canon-teal` / `--canon-amber` / `--canon-red`). The prototype's `--gold` should map to `--abarva-signal-blue` per `INTEGRATION.md`; everything else should use `--abarva-stone` (eyebrow on paper) or `--canon-gray-500` (eyebrow on cream).
- **Primary-action color:** `primaryAction` and `primaryActionLink` use signal blue, which is reserved for public surfaces. In-app primary actions must be ink-on-cream black per `.cursorrules` and `INTEGRATION.md`.
- **Sans-serif uppercase substituted for mono uppercase eyebrows:** Several places use Inter uppercase where the reference uses JetBrains Mono uppercase.
- **Phase rail re-implemented inline (and incompletely)** in two of three views; missing entirely from the home cards. Solving once with a shared component eliminates ~6 divergences at once.
