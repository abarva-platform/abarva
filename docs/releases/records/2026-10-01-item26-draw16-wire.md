## Status

## Plain-English Summary

The sixteenth stale-suite triage draw (P3 item 26) judged twenty test files
that no continuous-integration job ran. Its verdicts were recorded read-only in
#8779 (`docs/architecture/item26-draw16-stale-suite-triage.json`). Seven were
judged `wire_into_ci`: green, behavioural, reading no repository file, over a
subject neither unreachability registry lists. This change does that wiring and
nothing else.

All seven files were re-executed one at a time on base `0858491423` before
wiring: 7 suites and 59 cases, all green. They now run on every pull request in
two new steps of the `unit-suites` job:

- **Named by directory (6 directories, 6 suites, 37 cases):** the `lib` suites
  for `dependencies`, `email`, `enterprise-data/contracts`,
  `enterprise-knowledge/assembler`, `features` and `intelligence/binding`.
  `jest --listTests` over the six patterns resolves exactly the six drawn
  files, so naming each directory whole selects nothing else today, and a test
  file added there later also runs.
- **Named by file (1 suite, 22 cases):**
  `src/lib/intelligence/ask/response-policy.test.ts`, because
  `src/lib/intelligence/ask` as a pattern selects 30 suites, and that subtree is
  already excluded from a directory step for being red.

Thirteen rows stay held, by verdict, and are not wired: five `repair` rows and
two live-intake `update_with_reason_recorded` rows that wait on one data-lane
decision, the ledger migration-text case, and five rows whose subjects are
still listed as unreachable (held for T-775).

No product file and no drawn test file is edited.

## QA / Validation

**Re-execution on base.** Each of the 7 files alone (`--runTestsByPath`): 7/7
suites, 59/59 cases. The two step commands run exactly as written: 6 suites /
37 cases and 1 suite / 22 cases.

**Red first.** With the workflow steps and the amended control in place but the
record, baseline and census not yet updated, the draw 16 control failed 1 of
11 (the new wiring case). After they were updated it passed 11 of 11, and
`audit:test-ci-coverage:check` exits 0.

**Mutations.** Each was applied, run against the draw 16 control and the
dark-directory ratchet, and restored; the four files' checksums were compared
after restore.

| Mutation | Result |
|---|---|
| M1: the `email` directory removed from the directory step | 2 cases fail |
| M2: the `features` directory turned into `# <dir>` inside the folded command | draw 16 control 1/11 fails |
| M3: the response-policy file removed from the named-file step | 2 cases fail |
| M4: the held `src/lib/evidence/__tests__` directory added to the directory step | 2 cases fail |
| M5: one row's `wiredInThisItem` removed | 1 case fails |
| M6: the census reverted to the base copy | 1 case fails |
| M7: the dark-directory baseline reverted to the base copy | 1 case fails |

7 of 7 caught. A first attempt at M2 wrote the word as a quoted `"#"`, which is
an ordinary argument to the shell, not a comment; the control rightly passed
it, and the mutation was re-run unquoted.

**Same-scope baseline, `src/__tests__/behaviors`:** 171 suites / 1804 tests /
0 failing on a clean worktree at base `0858491423`, and 171 / 1805 / 0 on this
branch (the one new control case).

**Other gates:** `tsc --noEmit` exit 0; eslint on the changed test exit 0;
triage-record census reconciliation exit 0; the quarantine and reconciliation
node tests 14/14. The control imports no `src` module, so the behaviour
coverage floor is not moved.
