## Plain-English Summary

A one-line correction to the committed test-CI coverage census, and a mechanism
worth recording because the usual safeguard did not fire.

Three changes landed on `main` in close succession, each adding one test file.
Two of them regenerated the census from a base that already held the third's
file; the third regenerated from a base that held neither of the others'. All
three independently arrived at the **same** counts. Because the committed values
matched byte for byte, git had nothing to reconcile: the merges were clean, no
conflict was raised, and the last one squashed onto `main` carrying a number
that described **its own** base rather than the tree that resulted.

The merged tree holds one more test file than any of the three bases did, so the
committed census sat one low: `testFiles` 2877 where the tree regenerates to
2878, and `coveredTestFiles` 2713 where it regenerates to 2714.
`directoriesWithTests` and the per-directory breakdown were already correct —
only the file totals were affected.

This change regenerates both censuses against the current tree. Nothing else is
touched.

The mechanism is the part worth keeping: a census collision normally presents as
a merge conflict, and the standing response is to take `main`'s side and
regenerate. When two branches land on identical counts there is no conflict to
notice, the pull request reports mergeable and clean, and the drift only becomes
visible on the next change. A clean merge of this file is therefore not evidence
that the file is right.

## Known Gaps

- **The safeguard that missed this is unchanged.** Nothing yet detects the
  identical-counts case at merge time; it is caught on the next change, by the
  required census context. Making the merge itself notice would mean treating
  this file as generated rather than committed, which is a larger question than
  this correction.
- **Only the totals were wrong.** The per-directory breakdown happened to be
  unaffected because all three additions landed in directories that were already
  counted. A collision in a directory one side creates would also skew
  `directoriesWithTests`, and nothing here makes that case easier to see.
