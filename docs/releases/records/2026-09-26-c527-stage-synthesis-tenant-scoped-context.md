# Stage-synthesis context block scoped to the resolved tenant

## Release ID

`2026-09-26-c527-stage-synthesis-tenant-scoped-context`

## Status

`candidate`

## Plain-English Summary

One API route that writes a model prompt was attaching the same block of
demo/background context to every request, whichever tenant asked. That block
carries one fixture tenant's programme inventory, its named vendor selection,
an open attestation gap and a spend pressure — so any other signed-in tenant
asking this route to explain a lifecycle stage had those facts placed in the
model's system prompt and in the AI-egress audit record.

The route now asks the repository's own resolver which context belongs to the
requesting tenant, using the tenant the server already resolved for the request
— never a string taken from the request body. Tenants that are not the fixture
tenant get the general platform context and nothing else.

Two supporting changes were needed for that to actually hold at the
destination:

- The route's in-memory answer cache was keyed on instance, stage and state,
  with no tenant in the key. Scoping the prompt while leaving the cache shared
  would have meant the first tenant to ask about a stage decided what every
  later tenant was told about it — the leak returning through the one door
  nobody looks at. The tenant is now part of the key.
- The active client is now resolved before the cache is consulted rather than
  just before the egress call, because from that point it is an input to what
  is composed and to what is stored, not only to the audit record.

This is **one caller of the six** named by the backlog item, deliberately. The
item says not to land six model-input changes in one pull request.

## Layer Impact

- **Lane:** `global-control-lane`
- **Layer:** control/app — one API route handler. No schema, no migration, no
  loader, no adapter, no projection, no data-plane change.
- Product surfaces: the stage-synthesis drawer shared by the Source and Moves
  surfaces reads this route. What changes for a tenant that is not the fixture
  tenant is which background context the model was given; the route's status
  codes, headers, caching semantics and streaming shape are unchanged.

## Client Applicability

- **All clients:** yes — every tenant reaching this route gets context scoped to
  itself. No flag.
- **Specific clients:** the fixture demo tenant's answers are unchanged: it
  still receives its own full block, and a test asserts that rather than
  assuming it.
- **Internal only:** no.
- **Public/demo only:** no.
- **Feature flag:** none. Adding one would mean shipping a known cross-tenant
  context leak in the default arm.

## Changes Included

- `src/app/api/reasoning/stage-synthesis/route.ts` — modified: the unconditional
  context block is replaced by the tenant-scoped resolver keyed off the
  server-resolved active client; the active client is resolved earlier; the
  answer cache key carries the tenant.
- `src/app/api/reasoning/stage-synthesis/__tests__/route.invariants.test.ts` —
  new: behavioural cases that drive the real exported handler and observe what
  the model and the egress ledger were handed.
- `.github/workflows/reasoning-layer-guard.yml` — modified: a step that runs the
  reasoning ROUTE suites, not only `src/lib/reasoning`. The new cases landed in
  a directory no workflow ran, which the coverage census caught on the first CI
  run of this branch. The whole directory is named rather than one file, so a
  case added beside a future reasoning route is wired by being written.
- `docs/architecture/test-ci-coverage-census.json` — refreshed. The directory is
  recorded as **covered**: `coveredTestFiles` rises and `uncoveredTestFiles`
  does not, which is the difference between wiring the suite and merely
  restating that nobody runs it.
- `reports/data-standard/legacy-purge/*` — regenerated by `release-check.mjs`;
  one allowed historical reference added, from the dataset path quoted in the
  new test file's header.

## QA / Validation

**The defect was reproduced at the destination before any fix was written.**
Driving the real handler as a tenant that is not the fixture tenant, 38 context
lines scoped by the repository to the fixture tenant appeared in that request's
system prompt and in its egress prompt.

**Which caller, and why this one.** The item names six production files and
states that their per-caller blast radius is unmeasured. It was measured, by
driving each real handler rather than by reading it, and they do not behave
alike:

| caller | reaches a model for a tenant that is not the fixture tenant? |
|---|---|
| `/api/tower/ask` | **No** — the block sits in `buildAvaTowerAskPrompt`, which the exported `POST` never calls. Its only caller in the repository is its own test. |
| `/api/source/synthesis` | **No** — 404 before the prompt is composed. |
| `/api/programs/synthesis` | **No** — 404 before the prompt is composed. |
| `/api/reasoning/stage-synthesis` | **Yes** — 200, and every fixture-scoped context line reaches the system prompt. |

The two 404s have a fragile cause rather than a structural one, and that is
recorded as a separate item rather than treated as safety: both routes need a
per-tenant dataset directory that is present for no tenant in the repository,
so restoring one re-opens the leak on those routes with no code change at all.

**Red first, then green, same cases:**

- `npx jest --runTestsByPath src/app/api/reasoning/stage-synthesis/__tests__/route.invariants.test.ts`
- Before the fix: **2 failed, 1 passed** of 3.
- After the fix: **0 failed, 3 passed** of 3.

The one case that passes before the fix is the positive control, and it passes
by design: it asserts the fixture tenant keeps its own context, which the
unconditional block also satisfied. Without it, the negative assertions could
pass because no context reached the prompt at all.

**Four mutations, four caught.** Each was applied to the fixed route, the suite
re-run, and the route restored:

| mutation | result |
|---|---|
| M1 — restore the unconditional block (the deleted direction) | 1 failed |
| M2 — pass the fixture tenant's key as a literal (the re-spelled direction) | 1 failed |
| M3 — drop the tenant from the cache key | 1 failed |
| M4 — derive the tenant from a request-supplied string instead of the resolved client | 2 failed |
| control — restored | 3 passed |

M2 is the case the item asks for by name: a guard that only fails when the call
is deleted would be satisfied by re-spelling it. M4 is the acceptance clause
"never off a request-supplied string", made executable.

**Scope regression, measured against a clean baseline worktree checked out at
`origin/main`, same scope both sides** (`src/app/api/reasoning`,
`src/app/api/source/synthesis`, `src/app/api/programs/synthesis`,
`src/lib/reasoning`):

- baseline: **0 failing, 772 passing, 61 suites**
- this branch: **0 failing, 775 passing, 62 suites**

**Typecheck:** `tsconfig.tsbuildinfo` removed first, then
`NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit --pretty false` —
**exit 0**, no diagnostics. The exit code is the verdict here, not a grep: a
bare run exits 134 on this host with no output at all.

**Lint:** `npx eslint src/app/api/reasoning/stage-synthesis/` — exit 0.

**The new suite is wired into CI, and that was not true when it was written.**
The first CI run of this branch failed the coverage-shape census with
`+uncovered src/app/api/reasoning/stage-synthesis/__tests__` — the new control
existed and no workflow executed it, which is the defect class this backlog
exists against rather than a formatting complaint. Fixed by adding the step,
not by refreshing the census around it: after the change the census records the
directory as covered (`coveredTestFiles` up, `uncoveredTestFiles` unchanged),
and `npm run audit:test-ci-coverage:check` exits 0.

## Rollout Plan

Merge to `main`. The repo-owned ACA main deploy workflow builds the image and
shifts traffic; no manual Azure command, no migration, no data build, no flag
flip. Runtime effect is immediate on the new revision.

## Deployment Authority

- Repo-owned deploy workflow: `.github/workflows/aca-main-deploy.yml`, on merge
  to `main`. No other path is used or needed.
- Shared runtime mutators: none. This change runs no `az` command and touches
  no Container App template, revision weight, env var, secret or worker job.
- Approved image digest: produced by that workflow from the merge commit;
  recorded against this release once the run completes.
- ACA runtime invariant: to be proven after the deploy — Container App template
  image digest equal to the digest on the 100%-traffic revision.
- Worker image invariant: unaffected; no worker job image changes here.
- Feature/env flag update path: not applicable.
- Live signed-in proof required: **yes, and owed.** This changes a model input
  on a live answer path, and only a signed-in run can show what the surface
  renders for a tenant that is not the fixture tenant. It was not attempted in
  this change and this record does not claim it. The behavioural cases prove
  what the handler hands the model; they do not prove what a browser renders.

## Rollback Plan

Revert the single commit and let the deploy workflow ship the revert. No
migration, no data written, no state to unwind. The in-memory cache is
per-process and empties on the revision swap, in both directions; the only
observable consequence of the key change is that a client holding an ETag
issued before the deploy gets one 200 instead of one 304.

## Known Gaps

- **Five of the six callers named by the item are untouched.** That is the
  item's own instruction. The measurement above is the useful part of what this
  change leaves behind: the remaining work is not five equivalent edits.
- **This route still has no tenant fence on the instance itself.** A tenant that
  is not the fixture tenant can still ask about, and be answered about, the
  fixture tenant's own sourcing event and programme, because the instance is
  resolved from module fixtures with no ownership check. That is a larger
  defect than the one fixed here, it is out of this item's scope, and it is
  filed separately rather than folded in.
- **Two callers are safe today only because a directory is absent.** Recorded
  above and filed separately.
- **The signed-in acceptance is owed**, as stated under Deployment Authority.
