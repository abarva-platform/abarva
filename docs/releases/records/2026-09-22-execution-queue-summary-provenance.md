# 2026-09-22-execution-queue-summary-provenance — The queue refuses a board summary it did not produce

## Release ID

`2026-09-22-execution-queue-summary-provenance`

## Status

`candidate`

## Plain-English Summary

The execution board and the claimable work queue are generated by two scripts in
`scripts/exec/`. Older copies of those same scripts still exist outside the repository, they
still run, and they have drifted from the reviewed ones. Until now nothing could tell which
copy produced a given board summary or queue file, so a queue built by a stale generator was
indistinguishable from one built by the current, tested generator.

Two changes close that gap:

1. The board generator records its own identity — script name, the path it ran from, and a
   SHA-256 over its own bytes — in `source-board-summary.json`.
2. The queue generator compares that stamp against the board generator sitting beside it and
   **refuses to build**, writing nothing, when the stamp is absent or names a different
   generator. The message says what was expected, what the summary recorded, and that a
   superseded copy is the likely cause.

The rendered queue also now states, in its own header, which generators produced it — so a
reader can tell at a glance, and a file missing that line is identifiable as the output of a
superseded copy.

The absent case fails closed on purpose. Every summary written before this change carries no
stamp, so a guard that passed the unknown case would never fire on the only files that
actually have the problem.

## Changes Included

- `scripts/exec/build-source-board.mjs` — writes `summary.generator` (`script`, `ranFrom`,
  `sha256` over its own source bytes).
- `scripts/exec/build-execution-queue.mjs` — `assertSummaryProvenance()` refuses a summary
  with a missing or non-matching generator stamp; the rendered queue header names both
  generators.
- `scripts/exec/build-execution-queue.test.mjs` — seven new cases covering the absent stamp,
  a stamp from a different generator, the message content, and two guardrails.

## QA / Validation

Same command either side of the change, from a clean worktree cut from `origin/main`
`810ab345ff6f4f3247668947e699f58d2cb3834e`:

- `node scripts/exec/build-execution-queue.test.mjs` — baseline on unmodified `main`
  **133 passed / 0 failed**. With the new cases and no fix: **134 passed / 6 failed**
  (one of the seven is a guardrail and passes either way). After the fix:
  **140 passed / 0 failed**.
- `node scripts/exec/build-source-board.test.mjs` — **23 passed / 0 failed**, unchanged.
- **Six mutations, six caught.** Disabling the absent-stamp branch (2 failed), disabling the
  hash comparison (2), removing the board's stamp (suite aborts non-zero), dropping the
  stated cause from the message (1), dropping the header provenance line (1), and dropping
  the recorded path from the message (1).
- **One mutation exposed a weak assertion and the assertion was repaired, not the mutation.**
  Disabling the absent-stamp branch did not make the queue render — the next branch
  dereferenced the missing stamp and the process died with a `TypeError`, which is exit 1 and
  no output file, satisfying every refusal check written in terms of those two. The cases now
  require the refusal sentence and forbid a stack trace, so a crash can no longer pass as a
  control.
- **Proven on a real known positive, not only fixtures.** A superseded generator copy was run
  against a private copy of the operator documents; it wrote a summary with no `generator`
  key, and the repo-owned queue refused it by name and wrote no queue file.
- `npx eslint` on the three changed files — exit 0, no output.
- `NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit --pretty false` — exit 0, zero
  diagnostics, judged by exit code with `tsconfig.tsbuildinfo` removed first.

## Known Gaps

- **This cannot stop a superseded copy of the *queue* generator.** If an operator runs both
  superseded copies, no repo-owned code executes and nothing here fires. What the change does
  guarantee is that the mixed case refuses, and that a queue file produced by a superseded
  copy is identifiable on sight by the absence of the header provenance line. Removing the
  copies entirely is operator-side work outside this repository.
- The id-band rule reported by the queue has a band with no free numbers left for one of its
  filers. That is a range decision, is already printed by the queue on every run, and is not
  addressed here.
