# 2026-09-27-stage-beat-formatter-extraction — One shared module for the four stage-beat formatters

## Release ID

`2026-09-27-stage-beat-formatter-extraction`

## Status

`candidate`

## Plain-English Summary

Four modules that build the per-stage task and gate content on the Source canvas each carried their
own private copy of the same four small formatting helpers: how a dollar figure is written, how a
lever key becomes a DOM-safe id, which document a computed number can be cited to, and how a target
band reads when a lever has not computed. Four copies of one rule can drift apart independently, and
the citation helper in particular encodes a judgement that matters on a client surface — it names
the document a number came from, and it must read the facts the evaluator actually consumed rather
than every input the rule declares. An input that was declared but never consumed says nothing about
where the number came from, so citing it would print a document that fed nothing.

This change moves those four helpers into one module the four stage-beat builders import. No
behaviour changed. The change is proved rather than asserted: the full stage view is built for every
stage on every branch of that stage's signal, before and after, and compared character for
character against a snapshot generated on the commit before the extraction.

## QA / Validation

**Where the copies differed, and why the union is a move rather than a widening.** Three of the four
helpers were byte-identical across their copies. `citedDocFor` had two forms: two modules typed its
first parameter `ValueLeverResult` and two typed it `ValueLeverResult | undefined` with a `?.` guard.
The shared version is the second form verbatim — the wider of the two signatures already in the
tree. For a defined result the two are the same function, so the two callers that always pass a
defined result cannot observe a difference and the guard arm is unreachable from them. Nothing
gained a branch.

**Red first.** On `31641238a1` with the new suite copied in: **2 failed / 32 passed of 34**. The two
failures are the only cases that are about the extracted module, and they fail because it does not
exist there. The module is loaded inside those cases rather than at the top of the file precisely so
that the red-first count says what changed instead of failing everything.

**Green after.** Same suite on this branch: **34 passed of 34**.

**Scope baseline, same scope, same command, clean worktrees.** `npx jest src/lib/source/facts`:

| | suites | tests | failing |
|---|---|---|---|
| `origin/main` at `31641238a1` | 25 | 440 | **0** |
| this branch | 26 | 474 | **0** |

**Behaviour-preserving, proved at the destination.** Ten full stage views — four stages across every
branch of each stage's signal — serialized and compared character for character against the snapshot
generated on `31641238a1`. All ten agree. The ten snapshots are also asserted to be ten distinct
documents, so the comparison cannot pass by comparing one view with itself.

**Five deliberate breakages, each caught, each verified non-vacuous first.**

| mutation | failing cases | stages that failed by name |
|---|---|---|
| `citedDocFor` reads any cited input, not only consumed ones | 16 of 34 | all four |
| `usd` drops the thousands separator | 11 of 34 | all four |
| `idSegment` stops lowercasing | 9 of 34 | all four |
| `targetBandFor` ignores `insufficientEvidence` | 6 of 34 | the two that call it |
| `targetLabel` swaps low and high | 6 of 34 | the two that call it |

`targetBandFor` and `targetLabel` exist on two of the four modules only, so two stages is their whole
caller set rather than a coverage gap. The prescribed `citedDocFor` mutation is the one the item
names, and it fails a case that names each of the four stages individually.

**A finding, and a fixture the suite needed because of it.** Two of the four stages build their
cited row only inside the committed / realized task. With no award and no realization read they call
`citedDocFor` and discard its answer, so on that branch the prescribed mutation changes nothing a
reader can see, and a case asserting over it would have passed mutated and unmutated alike — the
shape where a shared helper looks covered on four callers and is covered on two. A third fixture
branch was added for exactly those two stages: the signal read together with a citation map whose
only citation sits on a declared input the evaluator never consumed. The suite asserts, per stage
and per branch, whether a cited row is rendered at all, and asserts that each stage's mutation
branch is one that renders one — so a future change that removes the row fails loudly instead of
making the mutation case quietly vacuous.

**Static checks.** `NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit --pretty false` exit `0`
with no diagnostics, judged by exit code. `npx eslint` over the six changed files exit `0`.
`npx jest src/components/source/canvas` 55 suites / 277 tests, all passing, as the consumer side.

**CI coverage, read off the workflow rather than inferred.** `.github/workflows/unit-suites.yml:255`
runs `npx jest src/lib/source/facts` as a directory, so the new suite is inside the required
`Unit suites` check without any wiring change.
