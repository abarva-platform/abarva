# 2026-10-01-item26-draw15-wire — Wire the fifteenth stale-suite draw's twelve green files

## Release ID

## Status

`candidate`

## Plain-English Summary

The fifteenth stale-suite triage draw (P3 item 26) judged twenty test files
that no continuous-integration job ran. Its verdicts were recorded read-only in
#8767 (`docs/architecture/item26-draw15-stale-suite-triage.json`). Twelve were
judged `wire_into_ci`: green, behavioural, reading no repository file, over a
subject neither unreachability registry lists. This change does that wiring and
nothing else.

All twelve files were re-executed one at a time on base `3160fbf55b` before
wiring: 12 suites and 94 cases, all green. They now run on every pull request
in two new steps of the `unit-suites` job:

- **Named by directory (10 directories, 10 suites, 78 cases):**
  `config/tenants`, `data/apexretail`, and the `lib` suites for `ai`, `answer`,
  `atlas/initiative-deep/joins`, `azure-connectivity`, `context-trust`,
  `corpus`, `cxo-intel` and `decisions`. `jest --listTests` over the ten
  patterns resolves exactly the ten drawn files, so naming each directory whole
  selects nothing else today, and a test file added there later also runs.
- **Named by file (2 suites, 16 cases):** `src/lib/agent/all-agent-doctrine.test.ts`,
  because `src/lib/agent` as a pattern would select every suite under
  `src/lib/agent/**`; and `src/lib/agent/quality/__tests__/cxo-answer-quality.test.ts`,
  because its directory holds a second file that already runs in
  `wave0:quality-gate`.

Eight rows stay held, by verdict, and are not wired: the toolUseLoop byte scan
(`rewrite_as_behavior`), the WorkspaceExplorer stale label
(`update_with_reason_recorded`) and six rows whose subjects are still listed as
unreachable (held for T-775).

No product file and no drawn test file is edited.

## Changes Included

- `.github/workflows/unit-suites.yml`: two steps, `Run the item 26 draw 15
  config, data and lib suites` (ten directories) and `Run the item 26 draw 15
  agent doctrine and CXO answer-quality suites by named file` (two files).
- `src/__tests__/behaviors/product-directory-ci-coverage.baseline.json`: the
  eleven wired directories that were dark are removed (89 → 78 entries).
  `agent/quality/__tests__` was partial, not dark, so it was never listed.
- `docs/architecture/test-ci-coverage-census.json`: regenerated with the
  repo-owned `--write`. Uncovered test files drop from 217 to 205; uncovered
  directories from 91 to 80; partial directories from 28 to 27.
- `docs/architecture/item26-draw15-stale-suite-triage.json`: the twelve
  `wire_into_ci` rows are marked `wiredInThisItem: true`, and `secondHalf`
  records the wiring base, the re-execution counts, the two step names and the
  rows still held.
- `src/__tests__/behaviors/item26-draw15-triage-record.test.ts`: the census
  case now requires the census to hold only the eight non-wire rows, and a new
  case requires every `wire_into_ci` row to be named in an item 26 draw 15 step
  (read from the parsed workflow, not grepped) and to be run per the census
  (absent from the held set, directory not dark), while no held row may be
  named in such a step. The step command is cut at the first word starting
  with `#`, because a `>-` block folds to one shell line in which `#` begins a
  shell comment.

## QA / Validation

**Re-execution on base.** Each of the 12 files alone (`--runTestsByPath`,
`--json`): 12/12 suites, 94/94 cases. The two step commands run exactly as
written: 10 suites / 78 cases and 2 suites / 16 cases, both exit 0.

**Red first.** With the workflow step and the amended control in place but the
record, baseline and census not yet updated, the draw 15 control failed 1 of
10 (the new wiring case). After the record, baseline and census were updated it
passed 10 of 10, and `audit:test-ci-coverage:check` exits 0.

**Mutations.** Each was applied, run and restored.

| Mutation | Result |
|---|---|

| M2: the CXO answer-quality file removed from the named-file step | control 1/10 fails |
| M3: both step names lose "item 26 draw 15" | control 1/10 fails |
| M4: the held toolUseLoop file added to the named-file step | control 1/10 fails |
| M5: one wired directory turned into `# <dir>` inside the folded command | control 1/10 fails (escaped before the shell-comment cut was added) |

| M6: one row's `wiredInThisItem` set back to false | control 1/10 fails |

8 of 8 caught. M5 initially survived: the same parse in the T-799 control
treats a shell-commented path as named. That control is not changed here.

**Same-scope baseline, `src/__tests__/behaviors`:** 170 suites / 1792 tests /
0 failing on base `3160fbf55b` (as reported by #8767, whose branch head this
base is), and 170 / 1793 / 0 on this branch (the one new control case).

**Other gates:** `tsc --noEmit` exit 0; eslint on the changed test exit 0. The
control imports no `src` module, so the behaviour coverage floor is not moved.
