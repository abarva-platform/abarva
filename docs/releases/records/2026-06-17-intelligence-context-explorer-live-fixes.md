# Intelligence Context Explorer Live Fixes

## Release ID

`2026-06-17-intelligence-context-explorer-live-fixes`

## Status

`candidate`

## Plain-English Summary

Fixes the live Context & Corpus Explorer so it no longer shows seeded insight cards or stale fixture counts, the Sentinel composer actually sends typed questions to the QA route, and the fact-summary route no longer depends on a chunk column that older lab databases may not have yet.

## Layer Impact

- **Lane:** `global-control-lane`
- **Schema layer:** Adds chunk-level `source_system` lineage for future direct source grouping while keeping the runtime read model compatible with older databases.
- **API/data layer:** Keeps insight reads live-only and supports on-demand significance-rule evaluation when the Insights tab opens against an empty `context_insights` table.
- **UI layer:** Removes hardcoded insight and count fallbacks, wraps the Sentinel composer in a real form, and renders honest loading/empty/error states.
- **QA layer:** Adds regression coverage for live insight evaluation, composer submit wiring, and single explorer shell rendering.

## Client Applicability

- **All clients:** No behavior change while `context_corpus_explorer_enabled` is OFF.
- **Specific clients:** Any tenant enrolled in `context_corpus_explorer_enabled`, including SkyHarbor when the flag is active.
- **Internal only:** No.
- **Public/demo only:** No.
- **Feature flag:** `context_corpus_explorer_enabled`.

## Changes Included

- `src/components/intelligence-v4/ContextInsightsFeed.tsx` — removes seeded insight fallback, evaluates empty live rows once, and repaints from live `context_insights`.
- `src/components/intelligence-v4/SentinelExplorerRail.tsx` — real form submit, DOM textarea fallback, and accessible submit label.
- `src/components/intelligence-v4/IntelligenceExplorerPage.tsx` and `src/app/intelligence/page.tsx` — remove fixture count props and show live summary loading state.
- `src/lib/intelligence/context-read-model.ts` — counts chunk coverage through stable `source_record_id` lineage instead of reading `enterprise_context_chunks.source_system`.
- `supabase/migrations/20260617010000_enterprise_context_chunks_source_system.sql` — adds and backfills optional chunk `source_system` lineage.
- Chunk writers update `source_system` for new CSV, bulk-review, and onboarding chunk writes.
- `src/scripts/intelligence/evaluate-context-insights.ts` and `npm run intel:context-insights:evaluate` — operator receipt for SkyHarbor significance-rule evaluation in the private Azure network.
- Focused regression tests under `src/components/intelligence-v4/__tests__/` and `src/app/intelligence/__tests__/page-corpus.test.tsx`.

## Rollout Plan

Merge to `main`, run the normal Azure Container Apps build/deploy, apply the additive migration, then run `npm run intel:context-insights:evaluate -- --tenant=skyharbor-air` from the private Azure operator job. The explorer remains gated by `context_corpus_explorer_enabled`; rollback can be immediate by removing the feature flag for a tenant.

## Rollback Plan

Turn off `context_corpus_explorer_enabled` for affected tenants to return them to the V3 Intelligence page. Code rollback is a normal revert. The `source_system` column is additive and can remain in place if code is rolled back.
