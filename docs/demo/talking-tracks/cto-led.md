# CTO-Led Talking Track

Use when the buyer wants technical depth first.

## Opening

"The question is not whether developers can use AI tools. The question is where AI changes the operating model of IT and where it creates noise. AbarVa starts with Apex context: application portfolio, org topology, DORA baseline, SPACE/DevEx signal, tool footprint, vendor contracts, and active Moves."

## What To Emphasize

- Portfolio segmentation before tool rollout: TIME x AI-fit.
- Baseline before rollout: 4-6 weeks of DORA, SPACE, DevEx, and tool utilization.
- TOM change: AI Platform, Knowledge Engineer, Fluency Coach, Governance Lead, DevEx Analyst.
- Dissent: METR slowdown, ghost productivity, tool sprawl, and reallocation gap.
- Dependency DAG: productivity Move depends on data foundation, AI governance, portfolio rationalization, talent strategy, and mainframe sequencing.
- Source separation: AMS optimization is not a developer-productivity gate; it is a vendor-portfolio workflow.

## Close

"For the CTO, the product value is that the answer becomes an executable architecture: Move gates, dependency edges, evidence, and audit. The model does not get to be persuasive without being governable."
