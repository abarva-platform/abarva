# CIO-Led Talking Track

Use when the buyer cares about governance, InfoSec, auditability, and enterprise control.

## Opening

"The CIO question is not only 'will this improve productivity?' It is 'can we govern this across applications, vendors, data classes, and audit obligations?' AbarVa treats AI productivity as a controlled decision workflow, not a tool memo."

## What To Emphasize

- AI Egress Control Plane: every model call goes through tenant policy, data sensitivity classification, redaction as needed, and audit logging.
- `clients.ai_policy`: tenant-specific control over provider routes, maximum data class, approval, and kernel-only mode.
- `ai_egress_audit`: prompt hash, response hash, provider, data class, policy decision, latency, token counts, and artifact linkage.
- Security and IP gate: model allowlist, retention, indemnity, and source-code/IP policy before broad rollout.
- Version-pinned answers: corpus, templates, tenant context, and reasoning trace.
- Sibling dependency: AI Governance and Data Foundation are first-class Moves, not footnotes.

## Close

"For the CIO and InfoSec team, the differentiator is controlled reasoning. Sentinel can advise, but it cannot bypass tenant policy or leave unaudited model traffic behind."
