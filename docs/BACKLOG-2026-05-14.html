Cross-cutting

☆ Data ingestion model — four tiers

How a new customer’s data actually gets in. Different segments have different sensitivity and refresh cadence, so they get different ingestion paths. Enterprise IT expects a tiered answer, not “we have an upload button.”

TierChannelUse caseWhen
1. App upload AbarVa UI (browser file picker) Ad-hoc: policy doc, single vendor contract, org chart update, exec interview transcript. Pilot default for low-volume / unstructured / one-off content.
2. Azure landing zone Per-tenant Azure Blob container. Customer drops via Azure Storage Explorer / AzCopy / their ETL. Recurring structured data: KPI snapshots, program inventory, IT financials, contract registry, operating telemetry. Production default for the 9 segments that refresh weekly/monthly.
3. Direct integration Azure Data Share / Snowflake Data Share / point connector (ServiceNow, Workday, Coupa). Live operational signals: incidents, change tickets, vendor renewals. Enterprise tier, when trust is established.
4. In-VPC ingestion AbarVa stack deployed into customer’s Azure subscription (B4); data never leaves their tenancy. Regulated industries (healthcare, banking, defense). Required for some accounts before they’ll sign.

Shared controls (apply to every tier)

ControlPilot baselineProduction target

Encryption at restAES-256 defaultCustomer-managed keys via Key Vault
AuthenticationSAS token with TTL / service principalEntra ID federation; no shared keys

Recommended pilot default: Tier 1 + Tier 2 combo. Tier 1 handles 5 segments that arrive as unstructured docs (enterprise_profile, compliance, industry_context, program_deliverables, ad-hoc evidence). Tier 2 handles the 9 segments that need recurring batch refresh. Both paths feed the same broker pipeline, same sensitive-data scan, same audit log, same per-tenant data plane.
