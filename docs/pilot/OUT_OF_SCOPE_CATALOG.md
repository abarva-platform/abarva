# Pilot Out-Of-Scope Catalog

## Purpose

This catalog gives AbarVa a ready answer when a pilot client asks "can you also
do X?" during the first pilot. It protects delivery focus, avoids informal
commitments, and makes expansion asks commercially clean.

The catalog is a draft menu for discussion. It does not approve the change-order
rate in `T054`; final rates and discounts still require founder approval and
SOW language.

## Operating Rule

If a request is not in the signed pilot scope, classify it before work starts:

| Classification | Action |
| --- | --- |
| Included | Confirm where the signed scope covers it and add it to the active plan |
| Minor clarification | Handle within the weekly pilot cadence if it does not add net-new work |
| Paid add-on | Use this catalog or create a custom estimate before execution |
| Deferred roadmap | Capture through product feedback triage and place in Now / Next / Later |
| Rejected | Record rationale when it creates security, tenant, legal, or delivery risk |

Do not start out-of-scope work from a hallway request, Slack note, or demo
conversation. Record the ask, classify it, and confirm the commercial path.

## Draft Add-On Menu

| Add-on | Likely ask | Draft price | Boundary |

| Expedited turnaround | "Can this be done this week?" | 25% uplift | Only when capacity exists and quality gates remain intact |

## Human Approval Path

1. Capture the request in the product feedback intake.
2. Identify whether the signed SOW already includes it.
3. If out of scope, select the nearest catalog item or create a custom estimate.
4. Confirm data, security, legal, and tenant-isolation impact.
5. Send a written change-order note before work starts.
6. Start only after founder approval and client written approval.

## Required Change-Order Note

Every change-order note should include:

- Request summary.
- Business reason.
- In-scope/out-of-scope classification.
- Draft price or estimate range.
- Timeline impact.
- Data/security impact.
- Required client inputs.
- Acceptance language.
- Expiration date for the estimate.

## Guardrails

- No cross-client or cross-tenant data loading.
- No live client data load without admin attestation and sensitive-data
  controls.
- No legal, procurement, or production security commitments by demo/chat.
- No autonomous AI decisioning; every consequential approval stays human-owned.
- No new connector implementation from this catalog alone; connector builds
  require a separate technical estimate.
- No date commitment unless capacity and release/QA path are confirmed.
