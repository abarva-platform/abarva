Source File Cabinet / Artifact Vault

Durable storage, versioning, and access for every artifact tied to a Source event. Implements the Addendum: no Source artifact may exist only in Downloads or browser memory.

Design

  • Azure Blob is the durable byte store — every artifact is uploaded via the shared object-storage adapter (managed identity) to canonical paths under the source-events bucket. No local-only or browser-only files.
  • Postgres is the metadata registry — source_artifacts (migration 20260610203000) records every artifact: group, type, title, file, blob location, version, status, evidence/citation linkage, approval state, lifecycle. RLS: service_role all + authenticated read scoped by tenant_key.
  • File Cabinet is the access layer — a per-event panel grouping Generated / Uploaded / Templates / Sessions / Approvals, with version + status chips and durable download links; history (superseded) is opt-in.

Versioning

Regenerating never overwrites. persistSourceArtifact computes the next version for an (event, type, group), uploads bytes at the versioned path, inserts a lifecycle_state='current' row, and flips the prior current row to superseded (back-linked via superseded_by_artifact_id). The default File Cabinet view shows current only; history is one toggle away. Every prior version remains downloadable.
