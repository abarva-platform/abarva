# Frozen dataset acceptance protocol

An end-to-end Source acceptance matrix is valid only for one declared dataset and build, migration ledger state, set of projection runs and read-model checksums, reporting cutoff, and digest-pinned deployment. The frozen window starts before the first signed-in step and ends after the last evidence capture. An operator records one matrix ID and immutable baseline JSON before the walk, then obtains a fresh observation JSON from the same governed sources after each checkpoint.

The baseline has `matrixId`, `windowStart`, `windowEnd`, and `snapshot`. The snapshot must name `datasetId`, `datasetVersion`, `buildVersion`, `migrationLedger` (`version` and SHA-256 `checksum`), every `projectionRuns` ID, every SHA-256 `readModelChecksums` value, `reportingCutoff`, the 40-character `deploySha`, and the digest-pinned `deployDigest`. All timestamps are explicit UTC values ending in `Z`; all checksums and image digests use `sha256:` followed by 64 hexadecimal characters. The observation repeats the complete snapshot, adds `observedAt`, and lists known `changes` with `kind` (`reload`, `migration`, `deploy`, or `projection`) and `occurredAt`. IDs and checksums must come from their source systems; the validator neither discovers nor invents them.

Run `npx tsx scripts/source/validate-frozen-acceptance.ts <baseline.json> <observation.json>`. Exit 0 means the supplied records are structurally complete, equal, observed inside the window, and report no change during it. Exit 1 invalidates the matrix and prints reason codes; exit 2 means the input cannot be read. A dataset reload, migration, deployment, or projection during the window invalidates the run even if the final version appears unchanged. Start a new window and matrix; do not relabel old screenshots or step results as current acceptance.

The check is fail-closed but not a live-state monitor. A passing pair is **not** proof that the supplied ledger, projection IDs, read-model checksums, or runtime digest match the data plane. Capture their independent readbacks, signed-in step evidence, and opposite-tenant checks separately. A genuine business, legal, security, finance, supplier, or signature gate cannot be replaced by this protocol or by demo self-approval.
