4 · The end-to-end load process today

Entry: Admin Context Layer → bulk upload (ZIP or loose multi-file + manifest.json) → POST /api/admin/context-layer/bulk-upload → runBulkContextUpload()
ZIP: server-side JSZip unzip · ≤25 MB zip · ≤5 MB/file · ≤40 files · ≤2,000 rows/CSV
Validate: manifest schema · template exists per file · path safety · attestation · sensitive-data gate (quarantine)
Mode — validate_only: checks only, no Blob, no DB writes
Mode — stage_and_enqueue: Blob stage → Azure Service Bus (q-context-ingestion-events) → private landing-zone worker (parses binaries: PDF/DOCX/XLSX)
Mode — stage_and_process (used for v2, CSV/JSON): Blob stage → parse → enterprise_context_chunks + structured promotion → enterprise_context_sources/records/facts
Why prior loads were incomplete: structured facts commit only in stage_and_process for CSV/JSON — binaries are rejected there; loads run from localhost can't reach the private DB; and there is no SQL load-audit, so partial loads were invisible. The v2 dataset is CSV-only and run via a VNet job specifically to close this.
