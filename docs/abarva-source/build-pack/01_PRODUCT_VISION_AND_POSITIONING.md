# 01 PRODUCT VISION AND POSITIONING

## Product Vision

AbarVa Source is an AI-led sourcing and vendor-selection workflow product inside the AbarVa platform.

Source helps enterprises run complex technology-services sourcing events with structured intelligence, governed artifacts, scorecard discipline, and value tracking. It is designed for technology sourcing decisions where the work is too strategic for a procurement portal and too operational to live in advisor decks.

## Category

Source occupies a new category between:

- technology sourcing advisory
- procurement workflow
- enterprise AI workbench
- value governance platform

It is not a replacement for procurement systems of record. It complements them by doing the strategy, intelligence, artifact, evaluation, and decision-support work that happens before and around procurement execution.

## User Value

Source should help users:

- classify the sourcing event and required rigor
- define scope with missing-input visibility
- generate structured sourcing artifacts
- govern scorecards before vendor evaluation
- manage vendor response periods
- prepare executive decisions
- connect sourcing work to projected and realized value

## Platform Relationship

AbarVa is the broader platform.

AbarVa Source is one product surface within that platform.

Nexus is the lead sourcing agent within Source.

Source should reuse:

- Pattern Fabric for sourcing archetypes and reusable logic
- Agent Fabric for Nexus, Sentinel, Atlas, and Steward
- Artifact Studio for generated work products
- Control Tower for portfolio visibility
- Value Ledger for projected and realized value

## Competitive Positioning

### Versus ISG, Everest, Gartner Advisory

Traditional advisory provides market knowledge, benchmarks, and sourcing support, but much of the work lives in decks, spreadsheets, and consultant memory.

Source should provide:

- persistent workflow state
- repeatable pattern packs
- governed scorecard defaults
- generated artifacts with traceability
- decision and value ledgers

### Versus Ariba, Coupa, and procurement suites

Procurement systems manage requisitions, vendor records, contracts, approvals, and spend workflows.

Source should handle:

- technology-services sourcing intelligence
- sourcing strategy design
- RFP/RFI artifact creation
- scorecard governance
- executive decision support
- value tracking

Source complements procurement systems rather than replacing them.

### Versus consulting firms

Consulting teams can run sourcing events manually, but quality varies and the institutional memory is usually not reusable.

Source should make the best parts of sourcing methodology systematic:

- pattern packs
- repeatable workflows
- evidence-backed artifacts
- explicit decision records
- value realization tracking

### Versus generic AI tools

Generic AI tools can draft documents but do not understand workflow state, stage gates, scorecard governance, vendor evaluation discipline, or value realization.

Source should not free-write blindly. It should generate only from:

- approved pattern packs
- captured client inputs
- stage context
- missing-input tags
- evidence and citation checks
- human review and lock states

## Positioning Statement

AbarVa Source is the agent-led sourcing workbench for enterprise technology-services decisions. It brings sourcing intelligence, artifact generation, scorecard governance, decision support, and value tracking into one governed workflow.

## What Source Must Not Become

- a disconnected product
- a demo-only interface
- a procurement portal skin
- a chatbot with files attached
- a template library with AI labels
- a set of hard-coded AMS screens
