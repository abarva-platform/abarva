# 14 IMPLEMENTATION SEQUENCE

## Phase 1: Foundation Scaffold

Status: already completed as prototype foundation.

Includes:

- Source route family
- Source component folder
- Source lib folder
- early dashboard prototype

Important:

- dashboard is prototype v0 only
- it is not final design authority
- do not extend it until reviewed

## Phase 2: Multi-File Build Pack

Status: current task.

Goal:

- create reviewable product/design/architecture blueprint
- separate anchor, product vision, IA, visual design, data, workflow, agents, artifacts, scorecard, value, alerts, implementation, acceptance criteria, wireframes, and component specs

## Phase 3: Review Build Pack

Reviewer confirms:

- product framing
- route model
- state model
- visual model
- data model
- component spec depth
- wireframe clarity

## Phase 4: Approve One Component Spec And Wireframe

No component implementation proceeds without explicit approval.

## Phase 5: Implement Approved Component Only

Codex implements the approved component or slice only.

## Phase 6: Visual / Design Review

Review for:

- density
- hierarchy
- executive-grade feel
- responsive behavior
- clarity of next action

## Phase 7: Refine Component

Refine based on review.

## Phase 8: Move To Next Component

Only after review and refinement.

## Phase 9: Agent Integration

Agent integration begins only after static UX is strong.

## Phase 10: Artifact Generation

Artifact generation begins only after artifact model is stable.

## Phase 11: Vendor Evaluation

Vendor evaluation begins only after scorecard governance is stable.

## Phase 12: Realized Value Ledger

Realized value tracking comes later after projected ledger and measurement model are stable.

## Current Rule

The next implementation should not proceed until this Build Pack is reviewed.
