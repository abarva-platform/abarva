# 10 ARTIFACT AND RFP GENERATION MODEL

## Artifact Types

- minimum data request
- sourcing event brief
- scope document
- sourcing strategy memo
- RFP/RFI package
- pricing template
- vendor Q&A tracker
- vendor response summary
- evaluation scorecard
- orals/BAFO guide
- vendor selection memo
- mobilization checklist
- projected value ledger
- realized value ledger

## Artifact Statuses

- Not Started
- Draft
- Needs Inputs
- Needs Review
- Approved
- Locked
- Superseded
- Archived

## Artifact Tiers

- Rich = decision-grade
- Outline = useful but incomplete
- Stub = dignified placeholder when prerequisites are missing

Rules:

- no fake content
- no “coming soon” filler
- stub must state what prerequisite is missing
- artifact metadata must be visible before content

## RFP / RFI Generation Model

Source does not free-write a full RFP blindly.

Generation sequence:

1. guided Nexus intake
2. pattern-pack template selection
3. client-specific input capture
4. artifact section generation
5. assumption and missing-input tagging
6. Sentinel validation
7. human/procurement/legal review
8. versioned editable artifact output
9. approval/lock before release

## Artifact Metadata

Every artifact should carry:

- artifact type
- event id
- stage
- status
- tier
- owner
- confidence
- version
- required inputs
- citations or evidence placeholders
- approval state

## Release Rules

Before release:

- required inputs must be present or explicitly waived
- assumptions must be tagged
- Sentinel validation must be complete
- required reviewers must approve
- artifact must be locked

## Anti-Patterns

- producing polished RFP text with missing inputs hidden
- treating “Draft” as releasable
- using generic consulting templates without sourcing archetype context
- generating vendor-facing artifacts before scorecard governance is stable
