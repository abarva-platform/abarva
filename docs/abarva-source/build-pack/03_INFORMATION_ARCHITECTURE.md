# 03 INFORMATION ARCHITECTURE

## Mental Model

Source is organized around one core object: the `Sourcing Event`.

The user moves from:

1. Source Dashboard
2. Sourcing Event
3. Nexus Engagement Canvas
4. Stage Workspace
5. Artifact Drawer, Scorecard Governance, or Value Ledger as needed

## Source Dashboard

The dashboard answers:

> What sourcing events are active, where are they stuck, what decision is needed, who owns the next action, and what value is at stake?

Belongs on dashboard:

- portfolio metrics
- active events
- waiting events
- at-risk events
- decisions needed
- Nexus alerts
- event list/table
- value at stake

Does not belong on dashboard:

- full event canvas
- scorecard editor
- artifact body content
- vendor scoring workflow
- long-form AI chat

## Sourcing Event

The event is the durable unit of work. It owns:

- archetype
- rigor level
- workflow stage
- lifecycle status
- owners
- blockers
- artifacts
- scorecard
- value ledger
- alerts
- Nexus guidance

## Nexus Engagement Canvas

The canvas is the main event workspace. It should include:

- top event header
- journey tracker
- left stage panel
- center active stage workspace
- persistent Nexus panel
- artifact drawer entry points
- lifecycle status
- alerts

## Drawers

Use drawers for:

- artifact inspection
- future-stage prerequisite explanation
- supporting evidence and citations
- detailed missing-input lists

Do not use drawers for:

- primary stage work
- scorecard governance
- full value ledger review

## Dedicated Pages

Use dedicated pages for:

- scorecard governance
- value ledger
- direct artifact route access

## Avoiding Fragmentation

Source should avoid page sprawl by keeping the event canvas as the center of gravity.

Rules:

- Dashboard is for portfolio triage.
- Canvas is for event management.
- Drawer is for artifact inspection.
- Dedicated pages are for complex governed surfaces.
- Nexus panel is persistent guidance, not a separate destination.
