Moves Board-Grade Deliverable Standard

How AbarVa turns a language model into a deliverable factory — multi-pass generation, governed evidence, a quality gate, and a board-grade render.

1. The shift

A language model can write well, but prose is not a deliverable. A board-grade artifact is controlled: every client fact is sourced, no internal plumbing leaks into client-facing text, the structure is complete, claims without evidence are flagged rather than fabricated, and the document is rendered to a real Office file with a title page, revision history, table of contents, and source register. AbarVa wraps the model in that control.

3. Governed evidence, never invented facts

Client facts come only from the committed, tenant-scoped evidence bundle. Each is rendered as a numbered citation [n] resolved in a Source Register at the foot of the document. Where a needed input is absent, the generator writes [MISSING EVIDENCE] or a client-to-complete placeholder — it does not manufacture a number to fill the gap. Attested intake (Diagnose / Design questions the client answered) enters the same governed path as cited claims.

4. The quality gate (hard blocks)

CheckWhy it blocks
Internal-tag leakageNo document_extract:*, tower_*, enterprise_context_*, chunk_id, fact_key, raw table names, or retrieval labels may appear in client text.
Missing Source RegisterEvery cited claim must resolve to a register entry.
Unsupported claimsQuantified or material claims without a citation are flagged and counted; a clean board-grade pass drives this toward zero.
Missing sections / tablesThe section contract for the deliverable type must be satisfied (exhibits present).
Title / client-to-complete hygieneProper title page; placeholders are explicit, never silent.

A deliverable that fails the gate is stored as preliminary (not board_ready) — the system never presents unfinished output as complete.

5. The ROI rule — Business Case derives, never authors

The Business Case does not invent ROI. It is the terminal node of the consulting story-arc — Discovery → Solution Approach → Roadmap → Estimates → Value Model → Business Case — and its numbers derive from the approved upstream estimates and value model. Absent those, the Business Case is preliminary / blocked, not board-ready. No fabricated ROI ever reaches a board packet.

6. Render standard

  • DOCX: title page, revision history, table of contents, running headers/footers, page numbers, formatted tables, 11pt body.
  • HTML: faithful preview for in-app review.
  • XLSX: estimate / value worksheets where the deliverable is a model.
  • Format follows intent; the same governed object renders to multiple formats.

7. Hard rules honored

  • No internal tags in client-facing documents. gate-enforced
  • No unsupported claims. gate-enforced
  • Do not fabricate ROI. enforced
  • No board-ready Business Case without approved estimates/value. enforced
  • No raw Claude prompt without a governed context bundle. enforced
  • Do not over-constrain the model into mediocrity — expert latitude inside the contract. by design
