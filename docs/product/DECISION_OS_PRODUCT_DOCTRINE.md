# AbarVa Decision OS Product Doctrine

## Highest-Level Principle

AbarVa converts enterprise AI ambition into evidence-backed, value-tracked,
execution-ready Moves, guided by agents that combine client context, industry
patterns, expert methodology, and governance discipline.

AbarVa is not an AI project-management tool, a strategy chatbot, a dashboard,
or a template library. It is the AI-native operating system for deciding,
designing, mobilizing, sourcing, and proving enterprise AI transformation.

## Core Design Doctrine

| Principle | Product meaning |
|---|---|
| Outcome-first, not feature-first | Every screen and response clarifies the decision, business outcome, evidence, and next action. |
| Agent as expert partner | Agents know the method, phase, industry, client context, failure patterns, and expected artifacts before advising. |
| Pattern-first intelligence | Runtime reasoning starts from tenant context plus curated industry, AI, value, sourcing, governance, artifact, and failure patterns. |
| Simple phase discipline | Moves follow Originate -> Charter -> Diagnose/Discover -> Design -> Roadmap/Business Case -> Mobilize -> Handoff. |
| Evidence-governed recommendations | Claims are labeled as client fact, pattern-backed, benchmark-backed, inference, or missing evidence. |
| Human-plus-agent operating model | Every AI use case defines what humans own, what AI drafts/recommends/automates/monitors, approvals, exceptions, governance, training, and value measurement. |
| Artifact-driven work | Conversations must produce usable work products: briefs, charters, baselines, designs, business cases, RFPs, mobilization plans, and value scorecards. |
| Executive simplicity, consultant depth | CXOs see readiness, value, blockers, and next action; maestros can inspect phase, evidence, artifacts, and decisions. |
| Challenge mode | Agents flag weak value case, wrong sponsor, missing operating model, data risk, over-automation, unsupported ROI, and pattern mismatch. |
| Value proof from day one | Every Move carries a value model tied to avoided waste, cost reduction, productivity, cycle time, revenue capture, risk reduction, adoption, or verified impact. |
| Context is the product | Every answer improves as client systems, vendors, contracts, KPIs, org, risks, evidence, and industry patterns improve. |
| Trust before automation | AbarVa earns trust through source basis, confidence, human approvals, editable artifacts, decision traces, audit logs, and explicit missing inputs. |
| One workspace | Home, New Move, Move Workspace, Artifacts, Source, and Tower should feel like one journey, not ten destinations. |
| Best-practice plus adaptation | The system applies proven methods and adapts them to the client's vertical, systems, operating model, and constraints. |
| Confidence over activity | The product emphasizes decision readiness, evidence readiness, value readiness, gate readiness, adoption readiness, sourcing readiness, and handoff readiness. |

## Runtime Implication

The runtime prompt doctrine in `src/lib/agent/all-agent-doctrine.ts` carries the
short form of this product doctrine:

- Outcome-first
- Pattern-first
- Evidence-governed
- Artifact-driven
- Human-plus-agent by design
- Challenge mode
- Value proof from day one

The full doctrine belongs in product, design, agent training, prompt reviews,
and eval scoring. Any future feature that increases activity but does not
increase decision readiness should be challenged.
