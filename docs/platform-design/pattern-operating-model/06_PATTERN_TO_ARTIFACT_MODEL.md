# Pattern to Artifact Model

## Purpose

Define how patterns produce or shape AbarVa artifacts.

## Artifact Outputs

Patterns can produce:

- RFP sections.
- Scorecards.
- Minimum data requests.
- Risk registers.
- Executive briefs.
- Vendor questions.
- Negotiation plans.
- Approval checklists.
- Value ledger assumptions.

## Artifact Tiers

### Rich

Allowed when required inputs, evidence, stage context, and approval context are sufficient for decision-grade output.

### Outline

Allowed when the structure is known but some client-specific inputs are missing.

### Stub

Allowed when only pattern-level structure can be generated.

## Missing Input Rule

Patterns should list missing inputs before generating an artifact. Nexus must not silently fill missing client facts.

## Evidence Rule

Artifacts can include pattern-level language without client citation only when clearly labeled. Client-specific claims need evidence and citations.

## Examples

### RFP Package

Pattern sections used:

- RFP section library.
- Required inputs.
- Vendor questions.
- Pricing model library.
- Approval checklist.

### Scorecard

Pattern sections used:

- Scorecard defaults.
- Rationale.
- Override guidance.
- Validation rules.

### Executive Brief

Pattern sections used:

- Value levers.
- Risks.
- Benchmark expectations.
- Decision options.

## Artifact Audit Trail

Every generated artifact should be able to trace:

- Pattern id.
- Pattern version.
- Sections used.
- Client inputs used.
- Missing inputs.
- Evidence/citations.
- Agent that generated or reviewed it.
