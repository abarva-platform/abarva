# Source Outsourcing Pattern Pack Standard

## Purpose

Define the required structure for Source outsourcing and managed services pattern packs.

Outsourcing is deep enough to demonstrate AbarVa's IP advantage. Source should know the difference between AMS, IMS, cloud operations, data platform managed services, ERP support, service desk, cybersecurity managed services, staff augmentation, digital build, and related sourcing archetypes.

## Required Sections

Every outsourcing pattern pack should include:

1. Scope model.
2. Required data baseline.
3. RFP section library.
4. Pricing model library.
5. Scorecard defaults.
6. Vendor response completeness rules.
7. Pricing normalization rules.
8. Common traps.
9. Negotiation levers.
10. Transition risks.
11. Approval gates.
12. Value levers.
13. Failure modes.
14. Validation rules.
15. Agent guidance examples.

## AMS Pattern Pack

### Purpose

Guide application managed services sourcing.

### Required Data

- Application portfolio.
- Incident/ticket volumes.
- Run/change split.
- SLA history.
- Current staffing model.
- Tooling and integration landscape.
- Contract/spend baseline.

### Typical Artifacts

- AMS RFP.
- Pricing workbook.
- SLA schedule.
- Transition plan.
- Scorecard.
- Vendor Q&A tracker.

### Scorecard Emphasis

- Delivery model and transition capability.
- Application portfolio understanding.
- SLA/operational governance.
- Automation and productivity.
- Commercial model.

### Pricing Considerations

- FTE baseline vs ticket-volume pricing.
- Transition cost.
- Change request model.
- Service credit structure.
- Tooling cost ownership.

### Negotiation Considerations

- Productivity commitments.
- Transition support included/excluded.
- Service credit enforceability.
- Innovation and automation roadmap.
- Flex-down and demand variability.

### Common Failure Modes

- Generic scope that vendors cannot price.
- Transition effort excluded.
- SLA definitions ambiguous.
- Change work underpriced.
- Incumbent knowledge transfer underestimated.

## IMS Pattern Pack

### Purpose

Guide infrastructure managed services sourcing.

### Required Data

- Server/cloud footprint.
- Network and storage inventory.
- Data center footprint.
- Ticket and incident volumes.
- Security and compliance requirements.
- Tooling and monitoring stack.
- Current run cost.

### Typical Artifacts

- IMS RFP.
- Asset inventory request.
- Pricing model.
- Transition/migration plan.
- Security operations requirements.

### Scorecard Emphasis

- Infrastructure operations capability.
- Cloud/data center expertise.
- Security and compliance operations.
- Automation/observability.
- Commercial flexibility.

### Pricing Considerations

- Unit pricing by asset type.
- Cloud operations model.
- Monitoring/tooling responsibility.
- Transition and transformation separation.
- Exit assistance.

### Negotiation Considerations

- Unit rate transparency.
- Automation commitments.
- Data center exit support.
- Security accountability.
- Tooling ownership.

### Common Failure Modes

- Asset inventory incomplete.
- Cloud operations scope ambiguous.
- Security responsibilities unclear.
- Transition plan under-specified.
- Tooling costs hidden.

## Data Platform Managed Services Pattern Pack

### Purpose

Guide sourcing for data platform operations, modernization support, and managed data engineering.

### Required Data

- Data platform architecture.
- Data pipeline inventory.
- Workload volumes.
- Data quality issues.
- Governance/security requirements.
- Cloud platform footprint.
- AI/analytics roadmap.

### Typical Artifacts

- Data platform services RFP.
- Data pipeline inventory template.
- Governance/security requirements.
- Scorecard.
- Pricing workbook.
- Transition plan.

### Scorecard Emphasis

- Data platform modernization capability.
- Migration factory and delivery approach.
- Domain/data model expertise.
- Cloud platform expertise.
- Governance/security/quality.
- Commercial model.
- AI/GenAI enablement roadmap.

### Pricing Considerations

- Platform operations vs project delivery.
- Pipeline volume and complexity.
- Data quality remediation.
- Cloud cost accountability.
- AI/analytics support options.

### Negotiation Considerations

- Outcome commitments.
- Data quality ownership.
- Cloud consumption accountability.
- Platform roadmap support.
- AI enablement capability.

### Common Failure Modes

- Pipeline inventory missing.
- Data quality responsibility unclear.
- Platform operations and modernization scope mixed.
- Cloud costs excluded.
- AI roadmap overpromised without capability.

## Agent Guidance Examples

- Nexus: "For AMS, do not release the RFP until the application portfolio and ticket baseline are usable."
- Sentinel: "The vendor response cannot be cited until uploaded evidence is parsed and validated."
- Atlas: "This outsourcing event carries transition-risk exposure because transition support is excluded from vendor pricing."
- Steward: "Evaluation is blocked because the scorecard is not locked."
