# Data Table and Portfolio Patterns

## Principle

AbarVa is table-forward. Tables should feel elegant, calm, and readable. They should reveal portfolio truth faster than a grid of decorative cards.

## Table Requirements

Tables should surface:

- Name or work object.
- Status.
- Stage/phase.
- Owner.
- Aging or due date.
- Value at stake.
- Risk/blocker.
- Next action.
- Evidence or readiness when relevant.

## Visual Rules

- Compact rows with enough whitespace.
- Text-first status.
- Minimal color.
- Clear numeric alignment.
- Value at stake should be easy to scan.
- Rows should open detail or drawer.
- Avoid decorative icon columns.

## Portfolio Rules

- Show the portfolio before asking the user to drill down.
- Keep cards to top-level synthesis, not every object.
- Use pressure signals for the top few items.
- Use table rows for the full operating queue.

## Anti-patterns

- Too many cards.
- Badge walls.
- Hidden next action.
- Value buried in secondary text.
- Row overflow that makes the page feel broken.
