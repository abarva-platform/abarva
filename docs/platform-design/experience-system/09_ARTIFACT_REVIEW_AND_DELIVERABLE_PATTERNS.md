# Artifact Review and Deliverable Patterns

## Purpose

Artifacts are governed work products, not static files. AbarVa must show lifecycle, evidence, review, approval, version, and audit state.

## Artifact Lifecycle

- Not Started.
- Draft.
- Needs Inputs.
- In Review.
- Changes Requested.
- Approved.
- Locked.
- Issued / Published.
- Superseded.
- Archived.

## Versioning Visual Pattern

Artifact cards and rows should show:

- Artifact name.
- Phase or stage.
- Version.
- Owner.
- Status.
- Evidence readiness.
- Missing inputs.
- Review/approval state.
- Last modified.
- Primary action.

## External Edit / Re-upload

- Exported documents may be edited in Office or Google Docs.
- Re-uploaded edits create a new version.
- Uploaded versions must be classified, compared, summarized, and validated before citation.
- Source remains the system of intelligence, workflow state, evidence, and audit history.

## Review and Approval

- Comments attach to artifact versions.
- Changes requested create a revision loop.
- Approval state must be visible before lock/release.
- Locked artifacts cannot be edited unless reopened.
- Reopening creates a new version.

## File-Type Chips

Allowed chips: DOC, PDF, XLS, PPT, NOTE, HTML, DATA.

Use compact text chips. Avoid excessive file icons.
