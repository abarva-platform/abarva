## ☆ Data ingestion model (cross-cutting · informs A2, B4, B5, C4)

Different segments have different sensitivity and refresh cadence, so they get different ingestion paths. Enterprise IT expects a tiered answer, not "we have an upload button."

| Tier | Channel | Use case | When |
|---|---|---|---|
| **1. App upload** | AbarVa UI (browser file picker) | Ad-hoc: policy doc, single vendor contract, org chart update, exec interview transcript | Pilot default for low-volume / unstructured / one-off content |
| **2. Azure landing zone** | Per-tenant Azure Blob container; customer drops via Azure Storage Explorer / AzCopy / their ETL job | Recurring structured data: KPI snapshots, program inventory, IT financials, contract registry, operating telemetry | Production default for weekly/monthly refresh |
| **3. Direct integration** | Azure Data Share, Snowflake Data Share, point connector (ServiceNow, Workday, Coupa) | Live operational signals: incidents, change tickets, vendor renewals | Enterprise tier — when trust is established |
| **4. In-VPC ingestion** | AbarVa stack deployed into customer's Azure subscription (B4); data never leaves their tenancy | Regulated industries (healthcare, banking, defense) | Required for some accounts before they'll sign |

### Shared controls (apply to every tier)

| Control | Pilot baseline | Production target |
|---|---|---|
| TLS in transit | TLS 1.2+ | TLS 1.3 + mTLS on Tier 2-4 |
| Encryption at rest | AES-256 default | Customer-managed keys via Key Vault |
| Authentication | SAS token with TTL / service principal | Entra ID federation; no shared keys |
| Audit log | Every ingest event logged | Immutable, SIEM-streamable |
| Sensitive-data gate | Pattern-based `sensitive-upload-guard` (shipped, B5a) | + Purview classification (B5b) |
| Retention / deletion | Customer-deletable via support | Customer-deletable via UI; auditable retention windows per segment |
| Network isolation | Public endpoint with TLS for Tier 1 | Private endpoint for Tier 2+; VNet peering for Tier 3 |
| Quarantine | Failed-scan files → quarantine container, surfaced to admin (B5c) | Same + auto-delete after retention window |

### Recommended pilot default

**Tier 1 + Tier 2 combo.** Tier 1 (UI upload) handles 5 segments that arrive as unstructured docs (`enterprise_profile`, `compliance`, `industry_context`, `program_deliverables`, ad-hoc evidence). Tier 2 (Azure landing zone) handles the 9 segments that need recurring batch refresh. Both paths feed the same broker pipeline, same sensitive-data scan, same audit log, same per-tenant data plane.
