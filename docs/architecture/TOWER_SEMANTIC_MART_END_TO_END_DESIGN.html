Tower Semantic Mart End-to-End Design

Source files to facts, graph, semantic mart, dashboard, chat, dossiers, and the rebuild plan.

Executive Summary

Tower must become the CIO command center. It should explain where IT money is going, what it is producing, which vendors, programs, risks, renewals, and AI bets need attention, and what evidence is missing before leadership acts.

Source files
  -> source registry and parsed rows
  -> canonical entities
  -> atomic facts and graph
  -> Tower semantic mart
  -> Tower read models
  -> dashboard and factual chat
  -> advisory dossier
  -> Claude/aVa synthesis
  -> verified Tower response

Non-Negotiable Product Contract

RuleMeaning
Dashboard and chat use the same metric definitionsA number visible on the dashboard must match the number spoken by chat.
Factual Tower questions do not call ClaudeTop initiatives, budget rollups, vendor spend, renewals, splits, and gaps are deterministic.
Claude receives dossiers, not raw substrateAdvisory questions get a curated, bounded packet with facts, gaps, options, caveats, and citations.
Dossiers are not alternate truthDossiers are generated from the semantic mart/read models, not hand-maintained truth.
Every numeric claim is traceableEach number maps to metric definition, source file, row, field, period, and tenant.
Latency is gatedFactual answers target 2-3 seconds. Advisory answers target 10-15 seconds.

Layered Data Design

1. Source filesPortfolio companies, programs, initiatives, budget lines, vendors, value, risks, operating metrics.
2. Source registryFile hash, upload run, row count, parser version, freshness, trust level.
3. Canonical entitiesTenant, portfolio company, function, program, initiative, vendor, contract, risk, metric.
4. Atomic factsEntity-field-value facts with period, units, confidence, and source row lineage.
5. Enterprise graphFunds, owns, supports, blocks, renews, measures, impacts, depends_on relationships.
6. Semantic martDim/fact model plus canonical metric formulas.
7. Read modelsPrecomputed dashboard and factual chat views.
8. DossiersAdvisory packets generated from read models for Claude/aVa synthesis.

Dossiers

Dossiers stay, but only as generated advisory packets. They must be built from the semantic mart and read models. They cannot serve as an alternate source of truth.

Question Bank And Evaluation Harness

The first execution artifact generates 6,330 Tower questions, including 3,840 metric-specific prompts. This is intentionally larger than a demo bank so it can catch dashboard/chat metric drift, missing read models, latency regressions, and dossier misuse.

CategoryCountPass Criteria
Metric questions3,840Metric values match read models and dashboard formulas.
Dataset questions900Rows, tables, charts, and gaps bind to the right dataset.
Cross-dimension questions800Joins are correct and cited.
Gap questions180Missing data is precise and field-specific.
Advisory questions600Dossier grounded, no fabricated numbers.
Fence/safety questions10 starter adversarial promptsTenant isolation, no raw IDs, no internal jargon.

Rebuild At Speed

Phase 0: Freeze and audit, 0.5 day. Inventory source files, metrics, chat paths, and legacy paths.
Phase 1: Tower data contract, 1 day. Lock source templates, canonical entity schema, fact schema, graph edges, metric formulas.
Phase 2: Load and validate, 1-2 days. Commit registry, rows, entities, facts, graph, and validation receipts.
Phase 3: Semantic mart and read models, 1-2 days. Build dimensions, facts, gap register, metric provenance, and read models.
Phase 4: Dashboard rewire, 1 day. Render all Tower views from read models only.
Phase 5: Chat rewire, 1-2 days. Deterministic factual path plus dossier-backed advisory path.
Phase 6: Evaluation bank, 1-2 days for first deterministic scoring pass. Score facts, latency, citations, and consistency across the generated 6,330-question bank.
Phase 7: Production proof, 0.5-1 day. ACA deploy, signed-in browser proof, HTML report, release record.

Definition Of Done

  • Source files and rows have lineage.
  • Facts and graph are committed.
  • Semantic mart metrics are populated.
  • Dashboard uses read models only.
  • Factual chat uses read models only.
  • Advisory chat uses generated dossiers only.
  • Claude never performs source-of-truth math.
  • Question-bank proof shows no dashboard/chat contradictions.
